# 自动弹琴工具 (Original Guitar Tool)

一个用于解析和播放原神「风物之诗琴」曲谱的简易工具。

## 简介

自动弹琴工具可以将文本格式的曲谱文件解析为带时间轴的音符序列，再通过模拟键盘按键在游戏中自动演奏。用户可以从预设的曲谱库中选择歌曲，并根据个人喜好调整播放速度。

## 功能特性

- **曲谱选择**：提供交互式界面供用户选择要演奏的歌曲
- **速度调节**：支持自定义演奏速度，默认读取曲谱第一行的倍速标注
- **曲谱解析**：自动解析标准格式的曲谱文件，输出带真实行号的时间轴
- **分段播放**：可从指定行号开始播放，方便练习
- **起奏缓冲**：按下 F8 后有 2 秒缓冲再开始，留出时间把焦点交给游戏窗口
- **暂停续奏**：演奏过程中按空格暂停，按 F8 从当前音符继续
- **暂停回退**：暂停后按 P 中止演奏并**返回选曲界面**，可直接换曲或换起始行重来
- **一键启动**：`弹琴.bat` / `转换.bat` 双击即可运行，自动提权、自动挑选可用的 Python 解释器
- **MIDI 转谱**：内置纯标准库的 MIDI → 曲谱转换器，支持批量转换
- **简谱转谱**：`获取谱子/jianpu_to_score.py` 直接读阿拉伯数字简谱（含八度点 / 减时线 / 增时线 / 附点 / 升降号 / 和弦 / 连音线），自动移调到全白键、自动吸附黑键、自动安置音域，转完先自检通过才落盘
- **谱图识谱**：`获取谱子/简谱识谱/识谱.py` 直接读简谱**图片**（PNG），自动切系统 / 分小节 / 认字形（自校准字模）+ 八度点 + 减时线 + 附点 + 连音线 + **三连音括号**，并**自动剔除彩色歌词 / 标注**（它们与音符同为深色墨，只有饱和度分得开），输出可编辑的简谱 txt，再交给上一步转成机器谱。零第三方依赖
- **转换质量可调**：不量化模式（`--step exact`）、琴域外音处置（`--max-octave-shift`）、倍速自动对齐（`--speed auto`）
- **长音可按住**：曲谱支持可选的第三列「按住毫秒」。MIDI 谱用 `--hold midi` 按真实时值生成，手工谱用 `获取谱子/add_hold.py` 按「弹满自己这一格」补齐；播放器会自动把它钳到不拖慢后续音符 —— 见「按住时长（长音）」一节

## 使用方法

### 方式一：双击启动（推荐）

| 脚本 | 作用 |
|---|---|
| `弹琴.bat` | 选曲并自动演奏。会自动申请管理员权限，并自动挑一个装了 `keyboard` 的 Python 解释器 |
| `转换.bat` | 把 `change_base/no/` 里的 MIDI 批量转成曲谱，见「用 MIDI 生成曲谱」一节 |

双击即可，不需要打开命令行。运行状态、选中的解释器、依赖检查结果都会打印在窗口里。

### 方式二：命令行

在项目根目录下执行：

```bash
python main.py
```

### 曲谱格式

曲谱文件应放置在 `scores/` 目录下，采用 `.txt` 纯文本（UTF-8），每行一个音符：

```
#0.9倍速              ← 可选：首行声明默认倍速
#前奏：               ← 以 # 开头的行是注释，仅作分节标记
158 vj                ← 间隔 158 毫秒，同时按下 v 和 j（和弦）
158                   ← 只有数字表示休止 158 毫秒
158 a                 ← 间隔 158 毫秒，按一下 a
320 a 700             ← 第三列可选：按住 700 毫秒（用来做长音 / 重音）
```

- 第一列是**距上一个音符的间隔毫秒数**（播放器逐行累加，不是绝对时间），实际间隔 = 毫秒 ÷ 倍速
- 换个说法：**第 i 行的间隔 = 从第 i−1 行走到第 i 行的时间**（所以「从这一行到下一行的时间」写在**下一**行上）；第 1 行的间隔就是**起手延迟**。**最后一行也必须有间隔值**，否则那个音符会被 parser 直接漏掉
- **每一行的间隔可以不一样**，解析器只做累加。所以曲谱并不要求是均匀网格 —— 这一点是「还原原曲真实节奏」的关键，见 `--step exact`
- 第二列是按键串，**连写即为和弦**，会同时按下
- 第三列**可选**：是按住多少毫秒；不写（或写 `0`）时按住 50ms。演奏时按键会真的被压住那么久，松手即止 —— 详见「按住时长（长音）」。`scores/` 里的曲谱现在基本都带这一列（新转出来的机器谱默认不写，要写就加 `--hold midi`，或事后用 `add_hold.py` 补）
- 键位对应原神琴的三组八度：高音 `Q W E R T Y U`、中音 `A S D F G H J`、低音 `Z X C V B N M`
- 21 键覆盖的最高音到最低音是 **36 个半音**（三组八度自然音阶），这是硬上限

## 用 MIDI 生成曲谱（推荐）

`获取谱子/midi_to_score.py` 可以把 MIDI 文件转成本项目的曲谱格式。**纯标准库实现，不需要安装任何第三方包**（自己解析 MThd/MTrk、变长 delta、running status、元事件与 tempo map）。

### 批量转换

1. 把 `.mid` / `.midi` 文件放进 `change_base/no/`
2. 双击 `转换.bat`（或在项目根目录执行 `python 获取谱子/midi_to_score.py`）
3. 结果：

| 位置 | 内容 |
|---|---|
| `scores/<MIDI同名>.txt` | 生成的曲谱，可直接在弹琴程序里选到 |
| `change_base/yes/` | 转换完成的 MIDI（自动从 `no` 移过来） |

行为说明：

- 自动读取 `no/` 下**所有** MIDI，按文件名顺序**逐个**转换
- 输出文件名与 MIDI 文件名**完全一致**，只把扩展名换成 `.txt`
- 某个文件转换失败会**留在 `no/` 不动**，不影响其他文件；结束时打印失败清单
- 如果 `scores/` 里已有同名曲谱，会先备份成 `xxx.txt.bak` 再写入，**不会静默覆盖**你手写的谱子
- `yes/` 里若有重名，新文件会存成 `名字_1.mid`，同样不覆盖

### 单文件转换

```bash
python 获取谱子/midi_to_score.py 我的歌.mid                          # 默认就是声部编织
python 获取谱子/midi_to_score.py 我的歌.mid -o scores/自定义名.txt
python 获取谱子/midi_to_score.py 我的歌.mid --melody-track 1        # 手动指定主旋律轨
python 获取谱子/midi_to_score.py 我的歌.mid --max-voices 2          # 最多同时弹 2 个音
python 获取谱子/midi_to_score.py 我的歌.mid --mode highest          # 回退到旧的单音线行为
python 获取谱子/midi_to_score.py 我的歌.mid --mode merge
python 获取谱子/midi_to_score.py 我的歌.mid --step exact            # 节奏最还原（不量化）
python 获取谱子/midi_to_score.py 我的歌.mid --hold midi             # 按 MIDI 真实时值写「按住毫秒」
python 获取谱子/midi_to_score.py 我的歌.mid --hold midi --hold-max 800   # 长音统一截到 800ms
python 获取谱子/midi_to_score.py 我的歌.mid --max-octave-shift 0    # 绝不挪八度，超域不弹
python 获取谱子/midi_to_score.py 我的歌.mid --speed 0.75            # 故意放慢到 3/4
```

命令行参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `midi` | — | MIDI 文件路径。**省略则进入批量模式** |
| `-o, --out` | `scores/<同名>.txt` | 输出路径（批量模式下忽略） |
| `--mode` | `voicing` | `voicing`=**声部编织**，每个时刻编一个小和弦（旋律 + 低音 + 填充）；`highest`=每个发声点只取最高音（旧行为，会把复音压成单音线）；`track`=只取指定轨；`merge`=合并所有非打击轨 |
| `--track` | `0` | `--mode track` 时使用的轨号（从 0 开始） |
| `--melody-track` | `auto` | `--mode voicing` 时手动指定主旋律轨号；省略 = 自动判断（先看轨名关键词，再按统计兜底）。**转换日志会打印每轨的角色判定**，觉得判错了就用它覆盖 |
| `--max-voices` | `auto` | `--mode voicing` 时每个时刻最多同时弹几个音；`auto` = 按原曲密度取 2~5，也可直接给 1~5 |
| `--min-interval` | `auto` | `--mode voicing` 时和弦内任意两音的最小半音间隔；`auto` = 按原曲和声密度取 3~6。设成 1~2 会允许相邻半音同时响（音簇，很刺耳） |
| `--bass-gap` | `12` | `--mode voicing` 时低音声部与旋律至少要拉开多少半音才保留（默认一个八度）；给个大数等于不要低音声部 |
| `--step` | `auto` | `auto` = 十六分音符网格，步长由 MIDI 速度算出；也可直接给毫秒整数；`exact` = **不量化**，按原始 onset 的真实间隔逐行写 |
| `--merge-ms` | `50` | 间隔小于该值算「同时响」：`--step exact` 按它并成和弦，`--mode voicing` 按它分组挑声部（= 播放器按键按住 50ms，更近的本来就分不开） |
| `--hold` | `none` | `none` = 不写第三列，播放器统一按住 50ms（**与加入该功能之前逐字节一致**）；`midi` = 按 MIDI 每个音的真实时值写第三列，长音会被真的按住 |
| `--hold-max` | `2000` | `--hold midi` 时写入的按住时长上限（毫秒）。MIDI 里带踏板的尾音动辄好几秒，琴上按住再久也不会更响，截掉可以避免弹完还要干等 |
| `--hold-min` | `0` | `--hold midi` 时写入的下限（毫秒）。设成 200 等于给每个音一个统一的重音；0 = 只保底 50ms |
| `--hold-round` | `10` | `--hold midi` 时按住时长的取整粒度（毫秒），0 = 不取整 |
| `--speed` | `1.0` | 写入首行的倍速。省略 = `1.0`（与原曲等长）；`auto` = 按谱子时长与原曲时长之比反推；也可直接给数字（小于 1 会变慢） |
| `--max-octave-shift` | `1` | 超出琴域的音最多挪几个八度，更远的不弹。`0` = 绝不挪八度、超域直接不弹；给个大数 = 全都挪回来、一个音不丢 |
| `--tonic` | `auto` | 调性；默认自动挑选吸附误差最小的调 |
| `--max-chord` | `6` | 和弦最大键数，超出的保留最高音 |
| `--section-cells` | `256` | 每多少格插一条分节注释（`exact` 模式按等效时长换算），`0` = 不插 |
| `--section-seconds` | — | 每多少秒插一条分节注释；给了就覆盖 `--section-cells` |
| `--no-pad` | 关 | 不把末尾补齐到 8 格的倍数（仅网格模式） |
| `--overwrite` | 关 | 直接覆盖已存在的同名曲谱（默认先备份成 `.bak`） |

### 转换质量提示（含 9 首实测数据）

先认清一条物理下限：**琴没有升降号，所以「走音」消不掉。** 9 首实测，落在琴域内的音里有 **14.3%** 会被吸附到相邻的自然音（差 1 个半音）—— 这是琴本身的限制，任何算法都改不了，只能靠换调性把它压到最低（`--tonic`）。

在此之上，转换报告会打印几个数字，重要性从高到低：

| 报告行 | 含义 | 怎么调 |
|---|---|---|
| 超出琴域、不弹 N 个音 | 曲子跨度超过 36 个半音，这些音落不到琴键上 | `--max-octave-shift` 控制：`1`（默认）只挪 1 个八度、更远不弹，实测丢 5.5%；`0` 绝不挪八度但丢 15.6%；给个大数则一个音不丢，但会有音差 2~3 个八度 |
| 挪八度 N 个 | 被平移整数个八度，音级正确但音区变了 | 越低越好。此前这里平均占 **24.8%**（音域窗口少算了一个八度的 bug），现已降到 **9.9%** |
| 量化平均误差 | 音符对齐到均匀网格时的平均偏移 | `--step exact` 模式下为 0；默认十六分网格在人工演奏的 MIDI 上平均偏 23~26% 格（最多 136ms），节奏会发飘 |

三个实用建议：

1. **要节奏还原就加 `--step exact`。** 谱子格式本来允许每行不同间隔，可以完全不量化。实测 8/9 首钢琴 MIDI 的触键本来就不在网格上，量化等于把演奏的微时序抹掉。
2. **曲子跨度大就调 `--max-octave-shift`。** 跨度在 36 半音以内的（例如《圣诞快乐，劳伦斯先生》）实测 0 挪八度、0 丢音，基本无损；跨度 70~90 半音的建议保默认，或者干脆人工编曲。
3. **默认的 `--mode voicing`（声部编织）会自动给每个时刻配和声**：旋律轨的最高音 + 低音根音（与旋律差 ≥12 半音才加）+ 至多 1 个填充音（两两相差 ≥3 半音）。实测 9 首的效果：

   | 指标 | 旧 `--mode highest` | 新 `--mode voicing` |
   |---|---|---|
   | 平均发声数 | 1.20 音/格 | **1.75 音/格** |
   | 和弦内相邻半音（刺耳音簇） | 20% | **5%** |
   | 超出琴域丢音 | 最多 243 个（鸟之诗 26%） | **全部 0**（选音时就按琴域筛过） |

   旧的 `--mode highest` 会把复音压成一条单音线（复音格占比 0~6%，而手工整理的旧谱是 31~45%），听起来发干 —— 想对比就用它转一遍。

想换参数重转同一首曲子，把 `.mid` 从 `change_base/yes/` 移回 `no/` 再跑一次即可。

## 按住时长（长音）

改动前播放器**每按一下就固定按住 50ms**，所以 MIDI 里一个 1.5 秒的长音和 30 毫秒的装饰音弹出来一模一样，全是断奏。现在曲谱可以带第三列，写明这个音按住多少毫秒。

### 生成

```bash
python 获取谱子/midi_to_score.py 我的歌.mid --hold midi
```

`--hold midi` 把每个音在 MIDI 里的真实时值写进第三列。**默认是 `--hold none`（不写），即保持原来的行为** —— 实测 9 首用默认参数重转，产物与旧版**逐字节相同**，所以老谱子和老流程都不受影响。

### 关键设计：按住时长会被钳制

播放器是**顺序阻塞**的（按下 → 等 → 松开），不是定时器：每一行实际占用的时间是「按住时长」，而它只在**还没到目标时刻**时才补睡。于是每一行能**还掉**的迟到上限，就是 **「到下一个发声行的间隔 − 按住时长」** —— 注意是「下一个**发声行**」而不是「下一行」：休止行不发声也不睡时间，它只把目标时刻往后推，正好充当还账的缓冲。

- 按住 < 间隔（**有余量**）→ 这点余量会把上一行攒下的迟到一次性还清，顺便吸收「按下 / 松开」本身的耗时抖动。
- 按住 ≥ 间隔（**没有余量**）→ 余量为零甚至为负，迟到**逐行累积**，整首越来越慢，密集段落里再也追不回来 —— 这才是必须钳制的根本原因。

而 MIDI 里超过一半的音，其时值本来就长于到下一音的间隔（钢琴踏板导致）。所以 `parser.py` 会把每个音的按住时长钳到 **「到下一个发声行的间隔 − 10ms」**：

- 钳的是「下一个**发声行**」，不是「下一行」。中间夹着的休止行什么都不做，按住跨过去完全无害（`128 a` 后面跟 5 行休止，按住可以一直延续到下一个音）；按「下一行」钳会把它误砍成 118ms。
- 留 10ms 余量（`HOLD_GAP_MS`）。它既是**还账额度**，也是**抖动吸收器** —— 真实环境里 `sleep` 和按键本身都要花零点几毫秒，没有这点余量，这些零头会逐行攒起来。
- 下限 `DEFAULT_HOLD_MS`（50ms）：MIDI 里十几毫秒的装饰音会被抬到 50ms，否则游戏可能收不到那次按键。只有间隔连 50ms 都容不下（极密段落）时下限才盖过上限，此时会稍微迟到一点，但**与加入第三列之前的行为完全一致**。
- 最后一个发声行没有下一个音，不钳上限。

同一套规则在**转换阶段**（`midi_to_score.py` 的 `cap_hold_list()`）也会跑一遍，所以写进文件的数字**本身就是最终按住时长**（`--hold-max 2000` 之类的上限也在这个阶段生效）。`parser.py` 里那次是兜底：它同样管得住手写的曲谱。两边规则一致，重复钳是无害的。

实测漂移（用**真实的 `player.py`** + 假键盘 + 虚拟时钟跑完整首，逐音对比按下时刻与谱面时刻）：`scores/` 里 **15 首全程零偏差**，只有 `unravel` 的 6 行例外 —— 那 6 行间隔只有 45ms，连下限 50ms 都容不下，各迟到 6.7ms，随后的余量把账全部还清，**末音偏差回到 0.0ms**。反过来，绕开钳制硬按 200ms（间隔 80ms）时余量为 0，迟到没有任何还账途径，**12 个音就累积 1323ms** 并且再也回不来。

### 9 首 MIDI 机器谱

写入文件的中位按住时长 / 有多少音本来长于到下一音的间隔（即会被钳制）/ 钳制后实际按住范围：

| 曲目 | 写入中位（已钳制） | 未钳制时会被压 | 钳制后实际范围 |
|---|---|---|---|
| 圣诞快乐，劳伦斯先生 | 290ms | **7%** | 50~2000ms |
| 克罗地亚狂想曲 | 140ms | 22% | 140~1750ms |
| 琵琶曲 | 340ms | 24% | 50~1430ms |
| A Little Story | 260ms | 44% | 50~2000ms |
| 梦中的婚礼 | 263ms | 49% | 160~2000ms |
| luv letter | 166ms | 50% | 70~2000ms |
| 鸟之诗 | 120ms | 52% | 110~510ms |
| 花之舞 | 198ms | 66% | 150~2000ms |
| 若能绽放光芒 | 178ms | 34% | 84~1682ms |
| 青空 | 334ms | 43% | 334~1022ms |
| 群青 | 212ms | 54% | 101~1100ms |
| 拂晓 | 194ms | 34% | 92~3254ms |
| 打上花火 | 240ms | **87%** | 50~740ms |

读法：**慢曲收益最大** —— 圣诞快乐只有 7% 被钳，时值几乎原样保留（290ms vs 原来的 50ms，长了近 6 倍）；**快曲只剩「连奏」效果** —— 打上花火 87% 的音时值长于到下一音的间隔，钳完就成了一条连续的音线，不会有「长音」的感觉。这也和直觉一致：间隔本来就那么短，手指不可能按更久。

**注意「写入中位」是钳制后的值**，也就是游戏里真正按住的时长 —— 转换阶段就调了和 `parser.py` 一样的钳制规则（`cap_hold_list()`），所以文件里写的数字就是实际会发生的时长，不会出现「文件写着 2000ms、实际只按 290ms」这种对不上的情况。

### 5 首手工谱

`unravel` / `the way i still love you` / `你离开的事实` / `富士山下` / `恶作剧` 这 5 首是人从简谱转出来的，没有 MIDI 时值可依。它们用一条**保住原有断句**的规则补第三列：

```
按住时长 = (本行的起点 → 下一个更晚的行的起点) − 10ms
```

也就是「这一行的音符弹满自己这一格」：

- 下一行是音符 → 两音之间只隔 10ms，连起来
- 下一行是休止 → 在休止开始前 10ms 松开，**休止依旧是静默** —— 作者用单格休止做出的断音（占全部休止的 87.9%）一字不改

| 曲目 | 音符 | 写入按住 | 休止区 | 倍速 |
|---|---|---|---|---|
| 你离开的事实 | 814 | 462ms（全部一致） | 105 | 1.9 |
| 恶作剧 | 478 | 160ms（全部一致） | 42 | 0.75 |
| the way i still love you | 803 | 148ms（全部一致） | 473 | 0.9 |
| 富士山下 | 658 | 90ms（全部一致） | 693 | 0.65 |
| unravel | 1194 | **50~790ms**，中位 80ms | 915 | 0.75 |

`unravel` 是唯一取值不整齐的一首：它本身混用了 90/80/45/800ms 四种间隔，另有一行 45ms 连下限 50ms 都容不下。

规则实现在 `获取谱子/add_hold.py`，可重复运行（**已经有第三列的行原样保留**）：

```bash
python 获取谱子/add_hold.py                    # 试运行，只打印计划
python 获取谱子/add_hold.py --write            # 写回
python 获取谱子/add_hold.py scores/unravel.txt --write --max 500
```

改之前的 5 首归档在 `scores/_旧版（无按住）_手工谱/`，想对比可以直接拷回 `scores/`。

> 注意「钳制」和「断句」是两件事：`parser.py` 的钳制是**时间安全**约束（只保证不迟到，跨过休止也允许）；`add_hold.py` 的规则是**音乐**取舍（在休止前就松手，保住断音）。`add_hold.py` 算出来的值天然满足钳制条件，所以文件里的数字 == 游戏里实际按住的时长。

## 制作自己的曲谱（手写路线）

### 更省事：直接吃简谱**图片**

`获取谱子/简谱识谱/识谱.py` 把简谱**谱图**（双手钢琴简谱，PNG）读成下一步要的简谱 txt，同样零第三方依赖：

```bash
cd 获取谱子/简谱识谱
python 识谱.py "Bad Apple（1）.png" "Bad Apple(2).png" "Bad Apple(3).png" \
    --head "1=C 4/4 138" \
    -o "../../简谱/Bad Apple（旋律）.txt" --bass "../../简谱/Bad Apple（伴奏）.txt"
```

**版面参数全部自动检测**，换曲子 / 换扫描分辨率都不用改代码：墨阈值（纸白 ×0.81）、字号尺度 `S`（= 数字行高 / 21，所有长度常量都乘它）、小节线位置、系统（行）区间、每系统小节数、两只手的分界。

四处**专门为印刷谱的装饰元素**留的通道：

- **彩色元素直接剔出数字候选**：歌词 / 力度记号 / 指法标注常印成彩色（Call of Silence 的英文歌词是纯 `#FF0000`），而音符数字是黑的 —— 灰度化后两者都是「深色墨」，阈值分不开。所以读图时额外解一张**饱和度掩码**，一个连通域里 ≥50% 像素是彩色的就判定为歌词，不进数字候选。**没有这条通道的后果很直观**：歌词整行被当成音符，产物里凭空多出 `0` / `5` / `1`，每小节拍数从 4 涨到 5~8，休止符 `0` 还会被塞进和弦里变成 `(1' 0)`，最后连音线对不上直接转不出来。
- **连音弧粘住小节线 → 墨柱判据**：在系统末尾，连音弧的尾端常常搭在终止小节线的肩上，8 连通后并成一个 33×121 的宽组件，过不了小节线「宽 ≤0.30 字高」那道闸，于是被当成字形拆出一个**假的 `1`**（同样会把真音吞进伪和弦）。修法是再判一次「竖长墨柱」：逐列数墨量，若最宽的一段满柱 ≤0.30 字高，它就是一整根小节线，连音弧只是旁边那些不满的列。
- **三连音括号 / 琶音波浪线**：`—3—` 括号的左右臂常被切成 2~4 段短线，臂长还有 3.6 字高的上限；琶音/刮奏的**波浪线**若与数字 8 连通（Da Capo 的低音谱表），会连出一个「波浪线粘数字」的大组件 —— 靠**方向翻转率**（>0.03/行）与**最长墨柱比**（>0.6 字高）把波浪线与真花括号分开，再从组件底部按「数字高度的窗口 + 一行里有 ≥3 行够宽的横杠」把被粘的数字救回来。
- **连音弧的中段平顶 ≠ 增时线**：`⎴` 形圆弧的平顶被阈值化切成一截 `hline`，高度恰与数字行同高、宽度也落在增时线的范围内，于是被当成增时线（每小节凭空多一拍）。判据是看它**两端有没有圆弧相接**：与某条弧的端点横向相接（≤8 字高）且同高，就只是弧的平顶 —— 实测 Da Capo 靠这条把 4 个错小节的拍数修回 4。⚠️ 但《拂晓》的同一道平顶被切成了 **5 段**、只有 1 段真的与弧头相接 —— 剩下 4 段横跨 535px 罩住每一列，**每列凭空多一条减时线**（六组三连音和弦于是全短 1/3 拍）。判据改成**链式传播**：与已认定的弧平顶同高（|Δcy| ≤2 字高）且横向相邻（间隙 ≤8 字高）的 `hline` 一并排除。真减时线不受影响（实测弧顶 1566 与数字底出来的减时线 1524 差 20 字高，阈值有 10 倍余量）。
- **小节线只印一小截（「短刻度」版式）**：《拂晓》把小节线画成固定 125px 的小竖杠、**居中于该谱表的最末行**（花括号也只罩下半截）。系统上沿是由小节线的纵向连续段推出来的，于是天然比真实谱表顶行低 1~2 整行 —— **顶音的数字整颗落在系统外**。这条最阴：它既不改拍数、也不改任何记号，产物看着完全「正常」，只有把图放大逐音对才看得出来。修法是**上沿救援的链式版**：数字压在小节线上沿之上时，若 ① x 与**同一小节内**已收进系统的数字对齐（≤0.5 字高）、② 纵向正上方且间距 ≤2.2 字高、③ 落在「上一系统底 + 0.5 字高」与「本系统上沿」之间，就逐级链接回来（**连同它自己的八度点一起**）。另叠三条护栏：只在「上沿确实切进最上一行」（≤0.40 字高）时才启用、救援对象必须满高（挡 `)` 被 OCR 成 `1` 这类）、以及与段落号 `(N)` 的括号串排除（括号是横向连续成串的，顶音与 `)` 隔 36 字高 —— 整条 `left+60S` 宽带不能直接砍，会丢顶音）。
- **救援带的边界不能用「投影常量」卡死**：上一条救援的纵向范围写成 `sy0 − DOT_MAX·S`（`DOT_MAX = 20`），在《拂晓》里算出 41.90px，而高八度点恰好印在 42px 处 —— **差 0.1px，整颗被排除**；同一份谱另一页的同类点 41px 就侥幸过关。后果是**同一素材两处读音不同**（`(3 3)` vs `(3' 3)`，放大图证两处字形完全一样），「同素材段落比对」当场报不一致 —— 一条 0.1px 的阈值巧合能扯出 6 行产物差异。修法是给**点**补一条**锚定在本系统数字上**的判据：点掉到带外时，只要它正对（|Δcx| ≤ 12S）本系统**已有的**某个数字、纵向间隙 ≤`DOT_MAX·S`，就照收（数字属于本系统，点自然也是；再用「上一系统底 + 0.5 字高」兜底，绝不跨系统）。教训：凡是把「投影出来的长度常量」当硬边界，都要再留一条**锚定在真实对象上**的退路。

- **救援回来的点会被两条路各收一次**：上一条救援（`_rescue_top`）会把「数字自己的八度点」一起捞回并 append 进该小节的 `inner`；而这颗点整颗落在点救援带内 → `_extra_dots` 又收了它一次，`self.dots[(si,bar)]` 里同一颗点出现两遍。**单看重复无害**（`dot_map` 只是把同一个 `U` 记两次），但「竖排和弦按序配对」的前提是「列内点的个数 == 数字个数」，多出来的那颗让计数永远对不上 → **整条配对被静默跳过** → 顶上那音同时拿到 `U` + `D`（写出不合法的 `3',`）而下一位丢点。实测《拂晓》的 A/B 用《诀别书》抓到：p3s8b4（@92）谱面是 `(3' 1')`（放大图证两颗点都在数字上方；且 `3` 已有高音点、不可能再带低音点），被读成 `(3', 1)`。修法 = `self.dots[(si,bar)]` 按 `id()` 去重（并打警告 `⚠ 点去重`）。教训：**两条救援路径收同一批对象，合并处必须去重** —— 凡是「靠计数判等」的判据最怕重复元素；这类缺陷不改拍数、不改音数，只有放大图逐音对才看得出。
- **琶音波浪线被当成小节线**：《我不曾忘记》第 3 页第 1 系统开头一串竖排琶音，它的**波浪线** w≈6px × h≈75px 同时过了小节线的两道闸（够高 ≥1.15 字高、够窄 ≤0.30 字高）→ 在 x421 处多切出一个 16px 的**假小节** → 该页小节计数 +1、**段落号整体错位 1**（版面推值把认对的 65/69/73/77 改成了 66/70/74/78），还造出一个 0 拍空小节；而拍数自检只报 2 条、**看不出是编号错**。修法是另立一对判据 `_looks_like_barline()`：真小节线**整根贯通**（最长单列连续墨段 = 1.00 倍高），锯齿线只有 0.21；再加「逐行中位 x 方向翻转 >0.06 倍高」给**断笔（虚线）小节线**留活口。⚠️ 上面「花括号 vs 波浪线」那对阈值（方向翻转 0.03 / 最长墨柱 0.6）**不能搬到这里**：小节线本身就是一根贯通柱（1.00），拿 0.60 当线会把波浪线**漏掉**成小节线，正是这个 bug 的成因。教训：**同一个字形（波浪线）在两套判据里是「要认出」和「要排除」两种角色，阈值标定完全不同、不能互搬**。
- **连音弧的平顶冒充增时线（弧体落到相邻谱表那一版）**：@37 第 1 小节低音谱表上有一条「黑 `5` → 灰 `5`」的连音弧，它的三段 hline（两端弯头 h≈11px + 中间细平顶 h≈2px）被版面归属**整组划给了旋律格**；平顶的 cy 距旋律行 cy 达 11.55S，正好从旧的 12S 容差里钻进来充当第 4 条 `-` → 读成 `5 - - - -`（5 拍，应为 4）。⚠️ 这条与上面「连音弧的中段平顶 ≠ 增时线」是**同一个字形、不同的失效路径**：`_arc_flat` 的前提是「页面上存在 `arc` 组件」，而这条弧**一个 `arc` 组件都不剩**（弯头全被归进 `hline`），前提不成立 → 整条判据失灵。修法 = 把「增时线 cy 与声部行 cy 的容差」从 12S 收到 **3S**：实测 12 首曲子的 **761 条真增时线全部落在 1.05S 以内**（0.00S ×402 / 0.47S ×239 / 0.48S ×117 / 1.05S ×2），全样本里 >1.05S 的**只有这一处**（取 3S：比实测最大值高 2.9 倍、比误判目标低 3.85 倍）。教训：**判据依赖的中间对象可能整类消失**（`arc` 全被归成 `hline`），所以凡是「先找 A、再据 A 判 B」的写法，都要留一条**不依赖 A** 的退路 —— 这里就是不依赖任何其他组件的物理事实：增时线本来就压在数字行的中线上。
- **拍号印在音符行里（分数式变拍号）**：绝大多数谱子只在页眉印一个拍号，正文里不再出现；但《别让我担心》把变拍号**印在音符流中**，写成「小号数字 / 一条分数线 / 小号数字」的**分数**，而且上下两个谱表各印一枚（同一个记号画了两遍）。前版把它读成 (a) 伪和弦 `(4 4)`、(b) 分数线当**伪增时线** `-`（一小节凭空多 2 拍），并且**期望拍数一律按曲首的 4/4 算** —— 于是 m1~m7（6/8·9/8·6/8·6/8·5/8·6/8·10/8）的期望全错，连「双手分界复核」「拍数配平」「夹层音归属」三套逻辑都跟着按错期望工作（实测把低声部两颗正当的音搬进了旋律）。修法四件套：① 候选池 `_meter_pool()` 把 `junk` 也收进候选（变拍号的小号数字常被分类成噪声）；② `_meter_cands()` 取 top-4 候选给下游裁决；③ `_detect_meter()` 以**分数线为锚**、按**记谱法硬约束**（分母 ∈ `{1,2,4,8,16,32}`、分子 1..16、折算拍数 ∈ [0.5, 8]）枚举所有组合、取代价最小者，并且**无论是否凑出合法组合，都先把整个分数从音符流里摘掉**（改标 `tsig`/`tsigbar`）—— 摘干净是硬要求，否则分数线一定会去当增时线；④ `Page.exp()` + `_fill_bar_beats()` 让印记**按阅读顺序延续**（跨系统、也跨页，直到下一个印记），没印拍号的小节不再被当成曲首拍号。再叠一层 `Transcriber._resolve_meters()` 二级仲裁：上下两份拷贝的读数**打架**时（字形证据已用尽），改用谱面事实 —— 该小节两只手各自都要走完整个小节时长，「两只手拍数相等且恰等于某个候选拍数」就是决定性证据。⚠️ **记谱法允许分数拍号，但本项目的简谱文本格式只有「一个」拍号（首行）**，所以 `jianpu_to_score.py` 会把 m1..m7 报成「不合拍号」—— 这是**格式限制、不是缺陷**，权威拍数校验以识谱器的逐小节（印记 + 延续）为准。（判据：`METER_DEN_OK` / `METER_NUM_MAX` / `METER_BEATS_OK` / `METER_DIST_MARGIN`。）
- **窄字形把附点推出窗外**：附点窗原来写成「数字**右缘** + `8 × 字宽`」（≈17.6px），这个宽度是按「实测点与数字的间隙只有 3~5px」标的 —— 但那只对**宽字形**成立。附点是按**字身推进量**（也就是数字的「字宽」而非「墨迹宽」）摆放的，实测点落在数字原点右侧 ≈18px 处；窄字形 `1` 的**墨迹**只有 7px 宽，它的右缘离点就有 11.5px > 8 倍字宽 ⇒ **整颗附点掉在窗外被丢**。症状：`~1/` 本该是 `~1/.`（灰附点八分 = 0.75 拍），每小节少 0.25 拍。修法 = 新增常量 `DOT_APPEND_XF = 14.0`（≈13px），替换 `dot_map` 与 `_unattributed_dots` 两处判据里的 `+ 8 * S`。⚠️ **不能顺手放到 20S**：曾经试过「20S + 点不落在其他数字横向范围内」的排除式，结果拍数错从 2/118 **暴涨到 25/118** —— `dot_map` 里八度点判定 `if ac:` 优先，多出一个候选就会把整颗点改判成附点。14S 刚好够窄字形的 11.5px、又够不着当年翻车的 19px。⚠️ **为什么必须直接认出来、不能靠配平兜**：旋律列那些附点其实一直被「拍数配平」(`self._fixes`) 靠「孤儿点 + 唯一解」这条物理证据**间接**补上，所以产物字节不变；但配平明确 `continue` 掉和弦列（`base.startswith("(")`）—— **和弦列上的附点配平根本修不动**，只能靠附点窗自己认出来（《别让我担心》的 4 处全在伴奏和弦列 `~(1 4,)/` 上）。⚠️ **14S 必须配守卫**：大字号谱（S≈2.1）上 14S≈29px 会**抢走隔壁数字的高八度点**（《若能绽放光芒》p2s2b4 实测：窄 `1` 右 22px 的点其实是 `5` 的高音点 —— cx 与 `5` 完全相同、在 `5` 顶上方 19px ≤ DOT_MAX·S，只因 `1` 印得比 `5` 高 32px 才落进 `1` 的 ±3S 纵向带；旧 8S 是靠「够不着」侥幸过关）。守卫 = a 分支加一条「**这颗点同时是别的数字的合理八度点**（横向 ≤12S、纵向间隙 ∈ (2S, DOT_MAX·S]）⇒ 禁止当附点」，三个常数全部复用八度点自己的窗口、与字号/行距无关。**守卫不能写成「与任何数字同 cx」**：会被**另一只手**同列对齐的数字误伤（《别让我担心》mel `5` cx297 vs bas 附点 cx295 差 2px，4 处真附点整批丢回）。
- **花括号吞掉左端长小节线（系统整颗蒸发）**：`find_systems` 的系统 y 区间 = 小节线的纵向连续段，而谱表左端那根「贯通上下两排谱表的长小节线」正是把上下两排短杠（各 ≈1.2 字高）桥接成一个连续 run 的唯一纽带；《TruE》的前奏与第 6 系统里这根长线**被花括号吞进了同一个连通域**（brace bbox 变宽 / 分成两颗），于是两排短杠中间断开 127~146px（> merge gap=20S）、各自又过不了 `60*S` 最小高度闸 → **双双被弃、整个系统蒸发**，产出直接从第 2 系统开始，且 `calibrate` 的段落号推值链把被救系统数成 3 小节、整页 `@` 标记全部错位（@5→@4、@25→@23）。修法 = 花括号**一系统恰好一枚、纵跨恰一个系统**（正常系统的花括号都紧贴某个 span）⇒ 「不与任何 span 重叠的花括号」就是被吞系统：① 用花括号 y 区间补成 span；② 从花括号连通域里按「整列贯通墨柱」（列墨 ≥0.9h 的最右窄 run，与缺陷 5 的 `_vbar_core` 同一判据）抠回被吞的长线、**合成 vbar**（否则 `bar_columns` 缺左边界 → 4 小节被切成 3）；③ ⚠️ 合成 vbar 必须**同时进 `self.items`** —— `calibrate` / `read_sections` 的推值链是**重新**从 `pg.items` 取 vbar 的，只塞进局部 `vb` 会让推值链继续数错（这个坑实测踩过：只进 vb 时 15 个段落号变「1…55」）。纯花括号（没吞线）不碰。**教训：凡「数出来的版面结构」，修补时必须让所有消费方（find_systems / bar_columns / calibrate / read_sections / render）看到同一份数据。**
- **旋律上声部整行印在花括号之上 → 上沿救援够不着 → 整行静默丢失**（《雨爱》，**工具层未修**）：本曲每系统**四行**（旋律上声部 / 旋律行 / 中声部 / 低音），第一行**整行**印在花括号之外（在 `sy0` 之上）。上沿救援（缺陷 8）的窗口是 `lo = sy0 − SYS_PAD_TOP·med_h`（`SYS_PAD_TOP ≈ 0.42` 字高 ≈19px），而该行高出上沿 `0.58~0.69` 字高（26~30px）⇒ **够不着**；又因「往和弦里塞音不改时值」，**拍数自检恒报 0 错**（首轮 `✓ 每小节拍数 = 4（90 个小节·声部，0 错）` = 假绿）。**判据 = 花括号的 y 范围恰好是 `(sy0+2, sy1−2)`** ⇒ 「在花括号内」的行必是谱表内行，超出即幽灵行（`audit_brace.log` 逐系统比对 + `probe_all.py` 列全部系统的 cy 簇并标出带外行）；⚠️ **不能按「数字行数」猜**（本曲 12 个系统里只有 3 个带幽灵行），也**不能只看页眉区**（本曲页眉是纯文字，幽灵行在 `sy0` 之上但低于页眉）。实测 **12 颗**（`@1` 4 / `@21` 5 / `@29` 3），补正判据 = 幽灵行数字与旋律行数字 **cx 逐一对齐**（12/12，偏差 ≤4px）**且附点状态逐一相符** ⇒ 同列即同时和弦。⚠️ 拿图证必须**放大到 8 倍**才分得清「附点」与「高八度点」、以及「`6'` 带不带减时线」。处置两条路：① 放宽救援阈值（**未采纳**：须全量 A/B 回归，且既有 12 首源谱图不齐）／② 简谱层补正并入同列成竖排和弦（**本轮采纳**）。⚠️ **记谱学注**：四分附点时值下两音不可能真同响，所以补出的「同列且都带附点」只是本工具的和弦语法表达。
- **三连音括号被假阳性顶掉 → 真三连音一个都没打标**（《悬潮》，**工具层未修**）：`_find_triplets` 的判据（小号数字 `h ≤ 0.85×字高` + 左右各紧挨水平段 + 水平段穿过数字中段）在本曲**只命中了 2 个假目标** —— 第 1 页 `triplets = [(1471, 1493, 358)]`（**页眉带 y≈353 的细体数字**，组件 `tloop label=1 cx=1481 cy=353`）、第 2 页 `triplets = [(115, 151, 1347)]`（**左边栏段落号 `(45)` 的 `4` 与左右括号**，组件 `tloop label=4 cx=130 cy=1338`）。而谱面里**真的** 3 个标记（`probe4.py` 全谱扫「小号且窄、左右同高接横线」只找到 **2 个真括号**：第 1 页 `kind=arc cx=1099 cy=1139 h=15`、第 2 页 `kind=arc cx=1099 cy=667 h=15` —— 与 2 处「多 0.50 拍」的小节**一一对应**）连同左右臂被版面**归成一颗 `arc`**：它虽然够小（`15 < 0.85×23 = 19.55`），但 `smalls` 的筛选硬要求 `kind == "glyph"` ⇒ **进不了候选**；`_find_triplets` 另有一套「水平段穿过数字中段」的判据，本曲真括号的两臂与 `arc` 主体同高相接、也没满足 ⇒ **两条通道同时在真标记上落空**。于是 `_tag_triplet_digits` 一个数字都没打 `triplet` ⇒ `eval_bar` 里 `trip = any(d.get("triplet") …)` **恒 False** ⇒ 真三连音一个都没写 `*`，谱面 `766` 按字面八分渲染成 `7/ 6/ 6/`（1.50 拍）而非 `7/* 6/* 6/*`（1.00 拍）⇒ 该小节凭空多 0.50 拍（2 处：第 15 / 39 小节）。⚠️ **日志会骗人**：识别时照报 `三连音括号 1 个（标记 3 与括号横线已从谱面摘除）`，看着像「认到了」，其实是那 2 个假目标各报一个。处置：**不修工具层**（`_find_triplets` 要同时容纳「真标记已被版式判成 `arc`」与「页眉细体字 / 段落号括号不该命中」，改动面大、须全量 A/B 回归），走**简谱层补正** `7/ 6/ 6/` → `7/* 6/* 6/*`（2 处）。⚠️ 与**缺陷 3** 的分界：缺陷 3 治的是「括号两臂被切成 2~4 段短线」，本条的括号是**整条路线都没走通**（真标记压根没被 `_find_triplets` 看见、且即便看见也因 `kind != glyph` 而筛不出）—— 一个「认全了但被切碎」，一个「压根没进候选」。

唯一还要人盯一眼的是**页眉**：调号 / 拍号 / 速度那一行常与标题美术字、叠排的 `4/4`、音符符号 `♩` 挤在一起，自动识别可能读串（Bad Apple 就读成了 `)C4/4))33`）。这时脚本会明确告警并退到默认值 `1=C 4/4 91`，按上面的办法用 `--head` 指定即可 —— 页眉只影响速度，不影响任何音高与节奏。

认得出的记号：数字音级、八度点（上/下；**灰音符的空心点也认**）、减时线（一 ~ 三条）、附点、增时线、连音线（含跨小节）、和弦、段落标记、**三连音括号**。识别完会打印**逐小节拍数校验**与**「同素材段落是否逐字相同」**，全绿才落盘。

> 竖排和弦的八度点要小心「就近归属」：三个数字竖着叠起来时，一颗点离上面数字的底边和离下面数字的顶边只差 1~2 px，纯属硬币面。一旦某颗数字被同时判成高八度 + 低八度（简谱里不可能，产物会写出 `5',` 这种非法 token），就改用**按序配对**：列内点的个数与数字个数相等、每颗点都落在墨块之外、配对后方向一致，才采纳。⚠️ 这类修复落地时还要留意**缓存失效时机** —— 声部归属（mel/bas）是在「试算」之后才写回的，而试算过程已经把按旧归属算出的结果塞进了缓存，退出循环后没有任何调用再重算，产物就会命中这份陈旧缓存。修法是让 `staff` 在试算**之前**切换、失败再切回，并同步清缓存。

产物是**可编辑的简谱**而不是机器谱 —— 好处是先打开看一眼、把错音改掉，再转机器谱：

### 原谱中途变速：`retime.py`

`jianpu_to_score.py` 只有**一个**全局速度，而印刷谱常在中途另写速度记号（小字印在段落号旁边，识谱器只认页眉那一行）。**《诀别书》**就是这种：页眉 `♩=100`，但 `(25)` 处标了 `♩=112`、`(101)` 处回到 `♩=100`、`(105)` 处 `♩=90` —— 占 70% 的中段会偏慢 10.7%、结尾 4 小节偏快 11%。`获取谱子/retime.py` 在**产物层**补这一步：按小节把间隔列（和按住列）乘 `基准速度 ÷ 该小节速度`。

```bash
python 获取谱子/retime.py "scores/诀别书（简谱转）.txt" \
    --base 100 --tempo "1=100,25=112,101=100,105=90" --write
```

- `--base` 是跑 `jianpu_to_score.py` 时 `--head` 里的速度，工具会拿它核对头部注释的 `N BPM`，不符直接报错。
- **默认试运行**，只打印时长与自检结果；落盘要显式 `--write`，写前把原文件备份成 `<名字>.bak`（幂等）。
- 语义上「第 i 行的间隔属于**上一格**所在的小节」（`parser` 是先累加间隔再记音，速度在新格**开始**时才切换）；逐行乘完就取整会累积漂移（112 BPM 每格 133.93→134，76 个小节漂到 80ms），所以它维护一个浮点理想时刻、对**累计**时刻取整再作差 —— 实测累计误差 ≤0.5ms。
- 自检会重跑 `parser` 回读、逐行核对按键列没变、并用 `jianpu_to_score.simulate` 验证**模拟播放零迟到**。

`获取谱子/jianpu_to_score.py` **直接读人类简谱（阿拉伯数字谱）**，纯标准库零依赖：

```bash
python 获取谱子/jianpu_to_score.py 简谱示例/欢乐颂.txt          # 默认写 scores/欢乐颂.txt
python 获取谱子/jianpu_to_score.py 我的简谱.txt --bpm 120 --dry-run   # 只自检不落盘
```

支持的记号：

| 写法 | 含义 |
|---|---|
| `1 2 3 4 5 6 7` | 音级（do re mi fa sol la si） |
| `0` 或 `·` | 休止 |
| `5'` / `5,` | 高八度 / 低八度（可叠：`5''` 高两个八度） |
| `5/` / `5//` | 减时线：八分 / 十六分（每多一个 `/` 再减半） |
| `5.` / `5/.` | 附点：时值 ×1.5（可与减时线叠加） |
| `5/*` / `5//*` | 三连音：时值 ×2/3（`5/*` = 1/3 拍 = 三连音八分），可与上两者叠加 |
| `-` | 增时线：把**前一个音**延长一拍（可连写 `- -`） |
| `#4` / `b7` | 临时升号 / 降号 |
| `(135)` / `(1 3 5)` | 和弦（同时按下；时值写在括号后，`/` `.` `*` 与单音同义，如 `(135)/`、`(1 3 5)*`） |
| `1 ~ 1` | 连音线：**同音**相连、时值相加（两端音不同会报错） |
| `\|` | 小节线：只用来校验每小节拍数，不计入时间 |
| `@前奏：` | 段落标记，原样写进产物当注释 |
| `#` 开头 | 注释，丢弃（`#4` 这类升号不算） |

首行可选写 `1=C 4/4 120`（调号 / 拍号 / BPM），省略按 `1=C 4/4 90`。

**三件自动完成的事**（琴只有 21 个**白键**，黑键一个都弹不出）：

1. **自动移调**：`1=G` 会整体下移纯五度、`1=D` 下移大二度、`1=F` 下移纯四度 —— 全落白键，你按原调写就行；
2. **黑键吸附**：`#4` `b7` 这类临时升降号吸附到最近的白键并**计数报告**（这是琴的物理限制，不是 bug）；
3. **音域安置**：先选不丢音的八度、再选不打断旋律轮廓的安置方式，放不下的才丢并计数（`--max-fold` 控制）。

转换后**自动自检**：行语法 / `parser` 回读逐项对账 / 均匀网格 / 按住上下限 / 音域 / 模拟播放零迟到 / 编码（UTF-8 无 BOM + 纯 LF + 末尾换行）。自检不过**不会落盘**（要确认可用 `--force`）。产物形态与项目里其它曲谱完全同构：**一行 = 一个最小格**（按需要取十六分 / 三十二分 / 六十四分，含三连音时取十二分），按住时长 = 本音自己的时值 − 10ms，所以休止格是**真静默**。谱面里出现三连音（`*`）时网格会自动细化到 1/12 拍 —— 只有含三连音的谱面会变长，纯二进制谱面的行数与格长**一字不变**。

可参考两份样例：`简谱示例/欢乐颂.txt`（真实旋律）和 `简谱示例/语法示例.txt`（上面每种记号各来一条）。产物可直接丢进 `scores/` 实弹。

**暂不支持**：带升降号的调号（`1=#F`）。三连音要写成 `6/*`（时值 ×2/3），而不是直接写 1/3 拍。

### 旧路线：字母搬运工 `txt_maker.py`

`获取谱子/txt_maker.py` 只认**已经手工转成 A~G 字母**的文本（`(CD) G · A`），间隔写死 90ms，没有调号 / 八度 / 休止时值 —— 等于节奏全靠手敲。适合极短的片段，正常用请走上面的简谱路线。

```bash
cd 获取谱子 && python txt_maker.py     # 产物写 机器谱的阶段性成果.txt，需手工搬到 scores/
python 获取谱子/add_hold.py scores/你的新谱.txt --write   # 再补按住时长（规则见「5 首手工谱」）
```

### 第三条路线：从零作曲

项目里三首原创曲都是脚本生成的，曲子写成一张**数据表**，改数据重跑即可（不用手敲）：

| 脚本 | 产物 | 织体 | 曲风 |
|---|---|---|---|
| `获取谱子/compose_晴风.py` | `scores/晴风-原创.txt` | 旋律 + 八分音符分解和弦（最多 5 键） | 轻快动漫风，C 大调，32 小节约 64 秒 |
| `获取谱子/compose_独吟.py` | `scores/独吟-原创.txt` | **单声部**（每行恰好 1 键） | 无伴奏吟唱，自然小调，32 小节约 77 秒 |
| `获取谱子/compose_雀跃.py` | `scores/雀跃-原创.txt` | **单声部**（每行恰好 1 键） | 雀跃的民谣性快板，C 大调，44 小节约 78 秒 |

```bash
python 获取谱子/compose_晴风.py     # 重新生成 + 自检
python 获取谱子/compose_独吟.py
python 获取谱子/compose_雀跃.py
```

`compose_晴风.py` 的曲子本体在 `BARS` 表里，每行一小节：

```python
#  (和弦根音级数, 旋律 [(格, 级数[, 八度])], 伴奏模式, 间隔毫秒)
(1, m((1, 1), (3, 2), (4, 3), (5, 5), (7, 3), (8, 2)), "full", 240),
    ↑ C 和弦      ↑ 第 1/3/4/5/7/8 格依次放 do re mi sol mi re
```

级数 1~7 = C D E F G A B，八度缺省 5（高音组），写第三个数可以降到低八度；伴奏模式 `full` / `short` / `thin` / `one` / `final` 控制左手密度。

`compose_独吟.py` 换了一种写法：`SONG` 里每项是 `(段落名, [小节, ...])`，一个小节是若干 `(格数, 级数, 八度)`，级数给 `None` 就是休止 —— 长音直接写成「占 N 格」，休止就是换气口。

`compose_雀跃.py` 沿用同一套 `SONG` 写法，但**行有三种身份**（`render()` 里标注）：

| 身份 | 含义 |
|---|---|
| `note` | 一个音的第一行 —— 发声 |
| `sustain` | 该音的后续行 —— 键还按着，没有新的起音 |
| `breath` | 休止行 —— 键已松开，**真静默**（换气口） |

触键用三个小函数写：`n(格, 级数[, 八度])` 连奏（按满本音时值）、`s(格, 级数)` 断音点音（只按 70ms，剩下的格子松手）、`r(格)` 休止。音区用 `L`（中音组）/ `M`（高音组，缺省）标注 —— 旋律主体在高音组，句尾下探中音组当落点，单声部也能听出「隐伏低音线」。

#### 两种「按住」写法（都安全，音乐含义不同）

按住时长的**上限**由 `parser.py` 统一钳到「到下一个发声行 − 10ms」，这是时间安全约束。在这个上限之内还有两种写法：

| 写法 | 效果 | 用在 |
|---|---|---|
| 按满到**下一个发声行** − 10ms | 键一路按到下一个音；中间的休止格只是「没有新的起音」，键还按着 | `compose_晴风.py`、`midi_to_score.py --hold midi` |
| 按满**本音自己的时值** − 10ms | 句尾长音松手之后，剩下的休止格是**真静默**（听得出换气） | `compose_独吟.py`、`compose_雀跃.py`、`add_hold.py` |

`独吟` 全曲 100 个音：125 格是「延长」（键还按着，37.5 秒）、24 格是「换气」（松手静默，共 7.2 秒）。两种写法都**不会累积迟到** —— 夹在中间的休止行不睡时间，正好把长音多占的那段还回去（实测两种都是 0.0ms 偏差）。

`雀跃` 的断音（`s()`）也是这个道理：按住 70ms 就松手，剩下的格子变成真静默 —— 十六分的点音听的是那 40ms 的缝，八分的点音（如第 15 小节的 `e^2s`）缝有 150ms，是真的「蹦」起来。

#### 自检报告里都查什么

脚本每次运行都会自检并打印报告，**其中几项是专门为「琴没有升降号、且音衰减慢」加的**：

| 检查 | 为什么 |
|---|---|
| 非法按键、按键顺序 | 和弦必须按「低音组→高音组」连写 |
| 和弦音簇（相邻 ≤2 半音） | 同时按下的音太近会刺耳 |
| 旋律撞根音小二/小九度 | 琴音衰减慢，上一个音还在响，**同时**相邻不刺耳的也要查 |
| 旋律相邻半音、跳进 ≥ 八度 | 同上；报告里列出来由人判断是不是想要的和声色彩（晴风 11 处全是 F↔E 的大七度色彩） |
| 音域 ≤ 36 半音、每行 ≤ 5 键 | 琴的物理上限 |
| parser 回读 + 模拟播放 | 产物真的能被工具读出来并弹完（三首都是 0.0ms 偏差） |

#### 「只用 14 个键位」的人声约束

> **这 14 个键 = 中音组 `asdfghj` + 高音组 `qwertyu`，即整个低音组 `zxcvbnm` 一个都不用。**
> 三组键位是：低音组 `zxcvbnm`(C3~B3) / 中音组 `asdfghj`(C4~B4) / 高音组 `qwertyu`(C5~B5)。
> 别把字母清单映射到错的那两组八度上 —— 写反了整首会掉到低音区。

`compose_独吟.py`（低吟）和 `compose_雀跃.py`（快板）都针对这个约束加了几项：

| 检查 | 为什么 |
|---|---|
| **每行按键数 == 1** | 「仅人声、无伴奏」落到谱面上就是单声部，出现和弦即违约 |
| **文件全文的 ASCII 字母 ⊆ `asdfghj` + `qwertyu`** | 约束说的是「只允许这 14 个键位」，那就把注释里的字母也一并管住（连 `A 段` 这种大写都不许出现）—— 直接断言整个文件的字母集合，比逐行查音符严格 |
| 低音组 `zxcvbnm` 用量 == 0、越界键位 == 0 | 同上 |
| 每个乐句（2 小节）至少 1 格换气 | 单声部没人换气就憋死了；最后一个乐句是收尾长音，豁免 |

`compose_独吟.py` 另外查「大跳（≥5 半音）后是否反向级进解决」—— 人声唱法，大跳之后要收回来才不别扭。
`compose_雀跃.py` 反过来**鼓励跳进**（灵动活泼），所以只报告跳进率与「连续同向跑动 ≥6 个」的处数供人判断，不断言：

| 曲目 | 跳进率 | 十六分占比 | 密度 |
|---|---|---|---|
| 独吟 | 35% | — | 1.3 音/秒 |
| 雀跃 | 45% | 69%（342/495） | 6.4 音/秒 |

#### 独立复核（不引用作曲脚本）

作曲脚本的 `self_check` 是「自己检查自己」—— 它对自己算出来的行下断言。`获取谱子/verify_original.py` 反过来，**只读落盘的字节**重新推一遍约束：

```bash
python 获取谱子/verify_original.py            # 复核 scores/ 下所有 *-原创.txt
python 获取谱子/verify_original.py 某个.txt    # 复核指定文件
```

两档：`vocal`（人声单声部，查 14 键白名单 + 单声部 + **注释里的字母也查**）、`free`（不受键位约束，允许 21 键与和弦，只做结构检查）。查行语法、首行 `#N倍速`、编码（UTF-8 无 BOM / 纯 LF / 末尾换行）、按住时长上下限、parser 回读一致、音域、时长。

> 写这个工具时踩到的坑：**间隔语义容易算反**。`parser.py` 是先 `current_time += interval` 再记音符，所以**第 i 行的间隔是给第 i+1 行的时间**；从第 x 行到下一个发声行 y 的间隔，是「第 x+1 行 … 第 y 行（含）」的间隔之和。只有用了两种以上间隔值的曲子（如晴风的 240/480）才会暴露这个 off-by-one —— 均匀网格的曲子两种算法结果一样，错了也看不出来。

## 模块说明

### parser.py

曲谱解析模块，提供以下函数：

- `parse(file_path, start_line=1)`：读取并解析指定路径的曲谱文件，返回 `Note(time, keys, line, hold)` 列表
  - `time`：距开始演奏的毫秒数
  - `keys`：需同时按下的按键列表（空列表表示休止）
  - `line`：该音符在曲谱文件中的真实行号（注释行、空行不参与计时但会占用行号，因此行号与编辑器一致）
  - `hold`：建议按住多少毫秒，**已经钳制过**（见「按住时长（长音）」）；`0` 表示用播放器默认值 `DEFAULT_HOLD_MS`（50ms）
  - 新字段加在末尾，所以 `note[0]` / `note[1]` / `note[2]` 和旧的 `Note(time, keys, line)` 三元组写法都还能用

### player.py

播放模块，提供以下函数：

- `play(notes, speed=1.0, start_time=0, start_line=1, start_delay=2.0)`：按下 F8 并等待 `start_delay` 秒缓冲后，按时间轴模拟按键播放
  - 每个音符的按住时长取 `note.hold`（为 0 时用 `DEFAULT_HOLD_MS` = 50ms），同样按倍速缩放：实际按住 = `hold ÷ speed`
  - **休止行不占时间**（只是把时间轴往后推），不会白睡一个按键时长
  - `start_delay`：起奏缓冲秒数，设为 `0` 可关闭；缓冲时间不计入音符间隔
  - 返回 `FINISHED`（整首弹完）或 `ABORTED`（暂停时按 P 中止）
  - 热键：F8 开始 / 继续，空格 暂停，暂停后按 P 中止并返回选曲

### 热键一览

| 按键 | 时机 | 作用 |
|---|---|---|
| `F8` | 选曲后 / 暂停中 | 开始演奏 / 从当前音符继续 |
| `空格` | 演奏中 | 暂停 |
| `P` | **暂停中** | 中止演奏，返回选曲界面 |

### main.py

主程序模块，提供以下函数：

- `choose_song()`：交互式曲谱选择
- `parse_default_speed(filepath)`：解析曲谱首行标注的默认倍速
- `main()`：程序主入口，内部循环 —— 演奏完成后退出；暂停时按 P 中止则回到选曲界面
