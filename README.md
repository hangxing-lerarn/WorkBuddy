# 自动弹琴工具 (Original Guitar Tool)

一个用于解析和播放原神「风物之诗琴」曲谱的简易工具。

## 简介

自动弹琴工具可以将文本格式的曲谱文件解析为带时间轴的音符序列，再通过模拟键盘按键在游戏中自动演奏。用户可以从预设的曲谱库中选择歌曲，并根据个人喜好调整播放速度。

## 功能特性

- **曲谱选择**：提供交互式界面供用户选择要演奏的歌曲
- **速度调节**：支持自定义演奏速度，默认读取曲谱第一行的倍速标注
- **曲谱解析**：自动解析标准格式的曲谱文件，输出带真实行号的时间轴
- **分段播放**：可从指定行号开始播放，方便练习
- **起奏缓冲**：按下 F8 后有 2 秒缓冲再开始，留出时间把焦点交给游戏窗口
- **暂停续奏**：演奏过程中按空格暂停，按 F8 从当前音符继续
- **暂停回退**：暂停后按 P 中止演奏并**返回选曲界面**，可直接换曲或换起始行重来
- **一键启动**：`弹琴.bat` / `转换.bat` 双击即可运行，自动提权、自动挑选可用的 Python 解释器
- **MIDI 转谱**：内置纯标准库的 MIDI → 曲谱转换器，支持批量转换
- **转换质量可调**：不量化模式（`--step exact`）、琴域外音处置（`--max-octave-shift`）、倍速自动对齐（`--speed auto`）
- **长音可按住**：曲谱支持可选的第三列「按住毫秒」。MIDI 谱用 `--hold midi` 按真实时值生成，手工谱用 `获取谱子/add_hold.py` 按「弹满自己这一格」补齐；播放器会自动把它钳到不拖慢后续音符 —— 见「按住时长（长音）」一节

## 使用方法

### 方式一：双击启动（推荐）

| 脚本 | 作用 |
|---|---|
| `弹琴.bat` | 选曲并自动演奏。会自动申请管理员权限，并自动挑一个装了 `keyboard` 的 Python 解释器 |
| `转换.bat` | 把 `change_base/no/` 里的 MIDI 批量转成曲谱，见「用 MIDI 生成曲谱」一节 |

双击即可，不需要打开命令行。运行状态、选中的解释器、依赖检查结果都会打印在窗口里。

### 方式二：命令行

在项目根目录下执行：

```bash
python main.py
```

> 用这种方式运行时，请以**管理员身份**打开终端，否则按键可能被 Windows 静默丢弃（原因见「注意事项」）。
> 曲谱目录基于 `main.py` 所在位置定位，因此在其他工作目录下同样可以运行。

### 操作流程

1. 运行程序后，将显示可用的曲谱列表
2. 输入对应曲谱的编号进行选择（输入 `q` 退出）
3. 输入起始行号（直接回车表示从第 1 行开始）
4. 输入倍速（直接回车表示使用曲谱自带的倍速）
5. 切到原神，打开琴界面并装备「风物之诗琴」，回到终端按回车
6. 切回**原神窗口**按 **F8** —— 按下后有 **2 秒缓冲**才开始弹奏
7. 演奏中按 **空格** 暂停；此时按 **F8** 从当前音符继续，或按 **P** 中止演奏并回到第 1 步重新选曲
8. 整首弹完程序自动退出

### 曲谱格式

曲谱文件应放置在 `scores/` 目录下，采用 `.txt` 纯文本（UTF-8），每行一个音符：

```
#0.9倍速              ← 可选：首行声明默认倍速
#前奏：               ← 以 # 开头的行是注释，仅作分节标记
158 vj                ← 间隔 158 毫秒，同时按下 v 和 j（和弦）
158                   ← 只有数字表示休止 158 毫秒
158 a                 ← 间隔 158 毫秒，按一下 a
320 a 700             ← 第三列可选：按住 700 毫秒（用来做长音 / 重音）
```

- 第一列是**距上一个音符的间隔毫秒数**（播放器逐行累加，不是绝对时间），实际间隔 = 毫秒 ÷ 倍速
- **每一行的间隔可以不一样**，解析器只做累加。所以曲谱并不要求是均匀网格 —— 这一点是「还原原曲真实节奏」的关键，见 `--step exact`
- 第二列是按键串，**连写即为和弦**，会同时按下
- 第三列**可选**：是按住多少毫秒；不写（或写 `0`）时按住 50ms。演奏时按键会真的被压住那么久，松手即止 —— 详见「按住时长（长音）」。`scores/` 里 15 份谱子现在都带这一列
- 键位对应原神琴的三组八度：高音 `Q W E R T Y U`、中音 `A S D F G H J`、低音 `Z X C V B N M`
- 21 键覆盖的最高音到最低音是 **36 个半音**（三组八度自然音阶），这是硬上限

## 用 MIDI 生成曲谱（推荐）

`获取谱子/midi_to_score.py` 可以把 MIDI 文件转成本项目的曲谱格式。**纯标准库实现，不需要安装任何第三方包**（自己解析 MThd/MTrk、变长 delta、running status、元事件与 tempo map）。

### 批量转换

1. 把 `.mid` / `.midi` 文件放进 `change_base/no/`
2. 双击 `转换.bat`（或在项目根目录执行 `python 获取谱子/midi_to_score.py`）
3. 结果：

| 位置 | 内容 |
|---|---|
| `scores/<MIDI同名>.txt` | 生成的曲谱，可直接在弹琴程序里选到 |
| `change_base/yes/` | 转换完成的 MIDI（自动从 `no` 移过来） |

行为说明：

- 自动读取 `no/` 下**所有** MIDI，按文件名顺序**逐个**转换
- 输出文件名与 MIDI 文件名**完全一致**，只把扩展名换成 `.txt`
- 某个文件转换失败会**留在 `no/` 不动**，不影响其他文件；结束时打印失败清单
- 如果 `scores/` 里已有同名曲谱，会先备份成 `xxx.txt.bak` 再写入，**不会静默覆盖**你手写的谱子
- `yes/` 里若有重名，新文件会存成 `名字_1.mid`，同样不覆盖

### 单文件转换

```bash
python 获取谱子/midi_to_score.py 我的歌.mid                          # 默认就是声部编织
python 获取谱子/midi_to_score.py 我的歌.mid -o scores/自定义名.txt
python 获取谱子/midi_to_score.py 我的歌.mid --melody-track 1        # 手动指定主旋律轨
python 获取谱子/midi_to_score.py 我的歌.mid --max-voices 2          # 最多同时弹 2 个音
python 获取谱子/midi_to_score.py 我的歌.mid --mode highest          # 回退到旧的单音线行为
python 获取谱子/midi_to_score.py 我的歌.mid --mode merge
python 获取谱子/midi_to_score.py 我的歌.mid --step exact            # 节奏最还原（不量化）
python 获取谱子/midi_to_score.py 我的歌.mid --hold midi             # 按 MIDI 真实时值写「按住毫秒」
python 获取谱子/midi_to_score.py 我的歌.mid --hold midi --hold-max 800   # 长音统一截到 800ms
python 获取谱子/midi_to_score.py 我的歌.mid --max-octave-shift 0    # 绝不挪八度，超域不弹
python 获取谱子/midi_to_score.py 我的歌.mid --speed 0.75            # 故意放慢到 3/4
```

命令行参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `midi` | — | MIDI 文件路径。**省略则进入批量模式** |
| `-o, --out` | `scores/<同名>.txt` | 输出路径（批量模式下忽略） |
| `--mode` | `voicing` | `voicing`=**声部编织**，每个时刻编一个小和弦（旋律 + 低音 + 填充）；`highest`=每个发声点只取最高音（旧行为，会把复音压成单音线）；`track`=只取指定轨；`merge`=合并所有非打击轨 |
| `--track` | `0` | `--mode track` 时使用的轨号（从 0 开始） |
| `--melody-track` | `auto` | `--mode voicing` 时手动指定主旋律轨号；省略 = 自动判断（先看轨名关键词，再按统计兜底）。**转换日志会打印每轨的角色判定**，觉得判错了就用它覆盖 |
| `--max-voices` | `auto` | `--mode voicing` 时每个时刻最多同时弹几个音；`auto` = 按原曲密度取 2~5，也可直接给 1~5 |
| `--min-interval` | `auto` | `--mode voicing` 时和弦内任意两音的最小半音间隔；`auto` = 按原曲和声密度取 3~6。设成 1~2 会允许相邻半音同时响（音簇，很刺耳） |
| `--bass-gap` | `12` | `--mode voicing` 时低音声部与旋律至少要拉开多少半音才保留（默认一个八度）；给个大数等于不要低音声部 |
| `--step` | `auto` | `auto` = 十六分音符网格，步长由 MIDI 速度算出；也可直接给毫秒整数；`exact` = **不量化**，按原始 onset 的真实间隔逐行写 |
| `--merge-ms` | `50` | 间隔小于该值算「同时响」：`--step exact` 按它并成和弦，`--mode voicing` 按它分组挑声部（= 播放器按键按住 50ms，更近的本来就分不开） |
| `--hold` | `none` | `none` = 不写第三列，播放器统一按住 50ms（**与加入该功能之前逐字节一致**）；`midi` = 按 MIDI 每个音的真实时值写第三列，长音会被真的按住 |
| `--hold-max` | `2000` | `--hold midi` 时写入的按住时长上限（毫秒）。MIDI 里带踏板的尾音动辄好几秒，琴上按住再久也不会更响，截掉可以避免弹完还要干等 |
| `--hold-min` | `0` | `--hold midi` 时写入的下限（毫秒）。设成 200 等于给每个音一个统一的重音；0 = 只保底 50ms |
| `--hold-round` | `10` | `--hold midi` 时按住时长的取整粒度（毫秒），0 = 不取整 |
| `--speed` | `1.0` | 写入首行的倍速。省略 = `1.0`（与原曲等长）；`auto` = 按谱子时长与原曲时长之比反推；也可直接给数字（小于 1 会变慢） |
| `--max-octave-shift` | `1` | 超出琴域的音最多挪几个八度，更远的不弹。`0` = 绝不挪八度、超域直接不弹；给个大数 = 全都挪回来、一个音不丢 |
| `--tonic` | `auto` | 调性；默认自动挑选吸附误差最小的调 |
| `--max-chord` | `6` | 和弦最大键数，超出的保留最高音 |
| `--section-cells` | `256` | 每多少格插一条分节注释（`exact` 模式按等效时长换算），`0` = 不插 |
| `--section-seconds` | — | 每多少秒插一条分节注释；给了就覆盖 `--section-cells` |
| `--no-pad` | 关 | 不把末尾补齐到 8 格的倍数（仅网格模式） |
| `--overwrite` | 关 | 直接覆盖已存在的同名曲谱（默认先备份成 `.bak`） |

### 转换质量提示（含 9 首实测数据）

先认清一条物理下限：**琴没有升降号，所以「走音」消不掉。** 9 首实测，落在琴域内的音里有 **14.3%** 会被吸附到相邻的自然音（差 1 个半音）—— 这是琴本身的限制，任何算法都改不了，只能靠换调性把它压到最低（`--tonic`）。

在此之上，转换报告会打印几个数字，重要性从高到低：

| 报告行 | 含义 | 怎么调 |
|---|---|---|
| 超出琴域、不弹 N 个音 | 曲子跨度超过 36 个半音，这些音落不到琴键上 | `--max-octave-shift` 控制：`1`（默认）只挪 1 个八度、更远不弹，实测丢 5.5%；`0` 绝不挪八度但丢 15.6%；给个大数则一个音不丢，但会有音差 2~3 个八度 |
| 挪八度 N 个 | 被平移整数个八度，音级正确但音区变了 | 越低越好。此前这里平均占 **24.8%**（音域窗口少算了一个八度的 bug），现已降到 **9.9%** |
| 量化平均误差 | 音符对齐到均匀网格时的平均偏移 | `--step exact` 模式下为 0；默认十六分网格在人工演奏的 MIDI 上平均偏 23~26% 格（最多 136ms），节奏会发飘 |

三个实用建议：

1. **要节奏还原就加 `--step exact`。** 谱子格式本来允许每行不同间隔，可以完全不量化。实测 8/9 首钢琴 MIDI 的触键本来就不在网格上，量化等于把演奏的微时序抹掉。
2. **曲子跨度大就调 `--max-octave-shift`。** 跨度在 36 半音以内的（例如《圣诞快乐，劳伦斯先生》）实测 0 挪八度、0 丢音，基本无损；跨度 70~90 半音的建议保默认，或者干脆人工编曲。
3. **默认的 `--mode voicing`（声部编织）会自动给每个时刻配和声**：旋律轨的最高音 + 低音根音（与旋律差 ≥12 半音才加）+ 至多 1 个填充音（两两相差 ≥3 半音）。实测 9 首的效果：

   | 指标 | 旧 `--mode highest` | 新 `--mode voicing` |
   |---|---|---|
   | 平均发声数 | 1.20 音/格 | **1.75 音/格** |
   | 和弦内相邻半音（刺耳音簇） | 20% | **5%** |
   | 超出琴域丢音 | 最多 243 个（鸟之诗 26%） | **全部 0**（选音时就按琴域筛过） |

   旧的 `--mode highest` 会把复音压成一条单音线（复音格占比 0~6%，而手工整理的旧谱是 31~45%），听起来发干 —— 想对比就用它转一遍。

想换参数重转同一首曲子，把 `.mid` 从 `change_base/yes/` 移回 `no/` 再跑一次即可。

## 按住时长（长音）

改动前播放器**每按一下就固定按住 50ms**，所以 MIDI 里一个 1.5 秒的长音和 30 毫秒的装饰音弹出来一模一样，全是断奏。现在曲谱可以带第三列，写明这个音按住多少毫秒。

### 生成

```bash
python 获取谱子/midi_to_score.py 我的歌.mid --hold midi
```

`--hold midi` 把每个音在 MIDI 里的真实时值写进第三列。**默认是 `--hold none`（不写），即保持原来的行为** —— 实测 9 首用默认参数重转，产物与旧版**逐字节相同**，所以老谱子和老流程都不受影响。

### 关键设计：按住时长会被钳制

播放器是**顺序阻塞**的（按下 → 等 → 松开），不是定时器：每一行实际占用的时间是「按住时长」，而它只在**还没到目标时刻**时才补睡。于是每一行能**还掉**的迟到上限，就是 **「到下一行的间隔 − 按住时长」**：

- 按住 < 间隔（**有余量**）→ 这点余量会把上一行攒下的迟到一次性还清，顺便吸收「按下 / 松开」本身的耗时抖动。
- 按住 ≥ 间隔（**没有余量**）→ 余量为零甚至为负，迟到**逐行累积**，整首越来越慢，密集段落里再也追不回来 —— 这才是必须钳制的根本原因。

而 MIDI 里超过一半的音，其时值本来就长于到下一音的间隔（钢琴踏板导致）。所以 `parser.py` 会把每个音的按住时长钳到 **「到下一个发声行的间隔 − 10ms」**：

- 钳的是「下一个**发声行**」，不是「下一行」。中间夹着的休止行什么都不做，按住跨过去完全无害（`128 a` 后面跟 5 行休止，按住可以一直延续到下一个音）；按「下一行」钳会把它误砍成 118ms。
- 留 10ms 余量（`HOLD_GAP_MS`）。它既是**还账额度**，也是**抖动吸收器** —— 真实环境里 `sleep` 和按键本身都要花零点几毫秒，没有这点余量，这些零头会逐行攒起来。
- 下限 `DEFAULT_HOLD_MS`（50ms）：MIDI 里十几毫秒的装饰音会被抬到 50ms，否则游戏可能收不到那次按键。只有间隔连 50ms 都容不下（极密段落）时下限才盖过上限，此时会稍微迟到一点，但**与加入第三列之前的行为完全一致**。
- 最后一个发声行没有下一个音，不钳上限。

同一套规则在**转换阶段**（`midi_to_score.py` 的 `cap_hold_list()`）也会跑一遍，所以写进文件的数字**本身就是最终按住时长**（`--hold-max 2000` 之类的上限也在这个阶段生效）。`parser.py` 里那次是兜底：它同样管得住手写的曲谱。两边规则一致，重复钳是无害的。

实测漂移（用**真实的 `player.py`** + 假键盘 + 虚拟时钟跑完整首，逐音对比按下时刻与谱面时刻）：`scores/` 里 **15 首全程零偏差**，只有 `unravel` 的 6 行例外 —— 那 6 行间隔只有 45ms，连下限 50ms 都容不下，各迟到 6.7ms，随后的余量把账全部还清，**末音偏差回到 0.0ms**。反过来，绕开钳制硬按 200ms（间隔 80ms）时余量为 0，迟到没有任何还账途径，**12 个音就累积 1323ms** 并且再也回不来。

### 9 首 MIDI 机器谱

写入文件的中位按住时长 / 有多少音本来长于到下一音的间隔（即会被钳制）/ 钳制后实际按住范围：

| 曲目 | 写入中位（已钳制） | 未钳制时会被压 | 钳制后实际范围 |
|---|---|---|---|
| 圣诞快乐，劳伦斯先生 | 290ms | **7%** | 50~2000ms |
| 克罗地亚狂想曲 | 140ms | 22% | 140~1750ms |
| 琵琶曲 | 340ms | 24% | 50~1430ms |
| A Little Story | 260ms | 44% | 50~2000ms |
| 梦中的婚礼 | 263ms | 49% | 160~2000ms |
| luv letter | 166ms | 50% | 70~2000ms |
| 鸟之诗 | 120ms | 52% | 110~510ms |
| 花之舞 | 198ms | 66% | 150~2000ms |
| 打上花火 | 240ms | **87%** | 50~740ms |

读法：**慢曲收益最大** —— 圣诞快乐只有 7% 被钳，时值几乎原样保留（290ms vs 原来的 50ms，长了近 6 倍）；**快曲只剩「连奏」效果** —— 打上花火 87% 的音时值长于到下一音的间隔，钳完就成了一条连续的音线，不会有「长音」的感觉。这也和直觉一致：间隔本来就那么短，手指不可能按更久。

**注意「写入中位」是钳制后的值**，也就是游戏里真正按住的时长 —— 转换阶段就调了和 `parser.py` 一样的钳制规则（`cap_hold_list()`），所以文件里写的数字就是实际会发生的时长，不会出现「文件写着 2000ms、实际只按 290ms」这种对不上的情况。

### 5 首手工谱

`unravel` / `the way i still love you` / `你离开的事实` / `富士山下` / `恶作剧` 这 5 首是人从简谱转出来的，没有 MIDI 时值可依。它们用一条**保住原有断句**的规则补第三列：

```
按住时长 = (本行的起点 → 下一个更晚的行的起点) − 10ms
```

也就是「这一行的音符弹满自己这一格」：

- 下一行是音符 → 两音之间只隔 10ms，连起来
- 下一行是休止 → 在休止开始前 10ms 松开，**休止依旧是静默** —— 作者用单格休止做出的断音（占全部休止的 87.9%）一字不改

| 曲目 | 音符 | 写入按住 | 休止区 | 倍速 |
|---|---|---|---|---|
| 你离开的事实 | 814 | 462ms（全部一致） | 105 | 1.9 |
| 恶作剧 | 478 | 160ms（全部一致） | 42 | 0.75 |
| the way i still love you | 803 | 148ms（全部一致） | 473 | 0.9 |
| 富士山下 | 658 | 90ms（全部一致） | 693 | 0.65 |
| unravel | 1194 | **50~790ms**，中位 80ms | 915 | 0.75 |

`unravel` 是唯一取值不整齐的一首：它本身混用了 90/80/45/800ms 四种间隔，另有一行 45ms 连下限 50ms 都容不下。

规则实现在 `获取谱子/add_hold.py`，可重复运行（**已经有第三列的行原样保留**）：

```bash
python 获取谱子/add_hold.py                    # 试运行，只打印计划
python 获取谱子/add_hold.py --write            # 写回
python 获取谱子/add_hold.py scores/unravel.txt --write --max 500
```

改之前的 5 首归档在 `scores/_旧版（无按住）_手工谱/`，想对比可以直接拷回 `scores/`。

> 注意「钳制」和「断句」是两件事：`parser.py` 的钳制是**时间安全**约束（只保证不迟到，跨过休止也允许）；`add_hold.py` 的规则是**音乐**取舍（在休止前就松手，保住断音）。`add_hold.py` 算出来的值天然满足钳制条件，所以文件里的数字 == 游戏里实际按住的时长。

### 试听差别

`scores/琴行为探针.txt` 末尾新增了第 6 段「按住时长」：同一个乐句先短按 50ms、再长按 450ms，另有和弦、密集连奏、按住 1 秒三种对照，弹一遍就能听出来。

## 制作自己的曲谱（手写路线）

如果不方便准备 MIDI，也可以从人类简谱转换。把整理好的简谱（形如 `(CD) G · A`，`·` 表示休止）放在 `获取谱子/` 目录下，运行：

```bash
cd 获取谱子
python txt_maker.py
```

生成的机器谱默认写入 `机器谱的阶段性成果.txt`，需要手工搬到 `scores/` 并补上 `#N倍速` 首行。

`txt_maker.py` 只输出「间隔 + 按键」两列，所以搬进 `scores/` 之后再来一步补上按住时长（规则见「5 首手工谱」）：

```bash
python 获取谱子/add_hold.py scores/你的新谱.txt --write
```

### 第三条路线：从零作曲（`获取谱子/compose_晴风.py`）

`scores/晴风-原创.txt` 是项目里的原创曲（轻快动漫风，C 大调，32 小节约 64 秒），由 `获取谱子/compose_晴风.py` 生成。它不是手敲的 —— 曲子写成一张**数据表**，改数据重跑即可：

```bash
python 获取谱子/compose_晴风.py     # 重新生成 + 自检
```

曲子本体在脚本的 `BARS` 表里，每行一小节：

```python
#  (和弦根音级数, 旋律 [(格, 级数[, 八度])], 伴奏模式, 间隔毫秒)
(1, m((1, 1), (3, 2), (4, 3), (5, 5), (7, 3), (8, 2)), "full", 240),
    ↑ C 和弦      ↑ 第 1/3/4/5/7/8 格依次放 do re mi sol mi re
```

级数 1~7 = C D E F G A B，八度缺省 5（高音组），写第三个数可以降到低八度；伴奏模式 `full` / `short` / `thin` / `one` / `final` 控制左手密度。按住时长不用手写，脚本按「弹满到下一个发声行 − 10ms」自动算。

脚本每次运行都会自检并打印报告，**其中几项是专门为「琴没有升降号、且音衰减慢」加的**：

| 检查 | 为什么 |
|---|---|
| 非法按键、按键顺序 | 和弦必须按「低音组→高音组」连写 |
| 和弦音簇（相邻 ≤2 半音） | 同时按下的音太近会刺耳 |
| 旋律撞根音小二/小九度 | 琴音衰减慢，上一个音还在响，**同时**相邻不刺耳的也要查 |
| 旋律相邻半音、跳进 ≥ 八度 | 同上；报告里列出来由人判断是不是想要的和声色彩（本曲 11 处全是 F↔E 的大七度色彩） |
| 音域 ≤ 36 半音、每行 ≤ 5 键 | 琴的物理上限 |
| parser 回读 + 模拟播放 | 产物真的能被工具读出来并弹完（本曲 0.0ms 偏差） |

## 模块说明

### parser.py

曲谱解析模块，提供以下函数：

- `parse(file_path, start_line=1)`：读取并解析指定路径的曲谱文件，返回 `Note(time, keys, line, hold)` 列表
  - `time`：距开始演奏的毫秒数
  - `keys`：需同时按下的按键列表（空列表表示休止）
  - `line`：该音符在曲谱文件中的真实行号（注释行、空行不参与计时但会占用行号，因此行号与编辑器一致）
  - `hold`：建议按住多少毫秒，**已经钳制过**（见「按住时长（长音）」）；`0` 表示用播放器默认值 `DEFAULT_HOLD_MS`（50ms）
  - 新字段加在末尾，所以 `note[0]` / `note[1]` / `note[2]` 和旧的 `Note(time, keys, line)` 三元组写法都还能用

### player.py

播放模块，提供以下函数：

- `play(notes, speed=1.0, start_time=0, start_line=1, start_delay=2.0)`：按下 F8 并等待 `start_delay` 秒缓冲后，按时间轴模拟按键播放
  - 每个音符的按住时长取 `note.hold`（为 0 时用 `DEFAULT_HOLD_MS` = 50ms），同样按倍速缩放：实际按住 = `hold ÷ speed`
  - **休止行不占时间**（只是把时间轴往后推），不会白睡一个按键时长
  - `start_delay`：起奏缓冲秒数，设为 `0` 可关闭；缓冲时间不计入音符间隔
  - 返回 `FINISHED`（整首弹完）或 `ABORTED`（暂停时按 P 中止）
  - 热键：F8 开始 / 继续，空格 暂停，暂停后按 P 中止并返回选曲

### 热键一览

| 按键 | 时机 | 作用 |
|---|---|---|
| `F8` | 选曲后 / 暂停中 | 开始演奏 / 从当前音符继续 |
| `空格` | 演奏中 | 暂停 |
| `P` | **暂停中** | 中止演奏，返回选曲界面 |

### main.py

主程序模块，提供以下函数：

- `choose_song()`：交互式曲谱选择
- `parse_default_speed(filepath)`：解析曲谱首行标注的默认倍速
- `main()`：程序主入口，内部循环 —— 演奏完成后退出；暂停时按 P 中止则回到选曲界面

## 注意事项

- 演奏期间 **原神窗口必须保持前台焦点**，模拟按键会发送给当前活动窗口
- **原神以管理员权限运行**，而 Windows 的 UIPI 会**静默丢弃**普通权限进程发出的按键 —— 表现为「脚本日志正常、游戏毫无反应」，且不报任何错误。`弹琴.bat` 会自动申请提权；若手动运行 `python main.py`，请以**管理员身份**打开终端
- `keyboard` 依赖必须装在你实际使用的那个 Python 里。本机同时存在多个 Python，`弹琴.bat` 会逐个候选测试 `import keyboard`，自动挑一个可用的；若提示缺少依赖，按窗口里打印的命令执行 `pip install -r requirements.txt`
- `转换.bat` 与 `midi_to_score.py` **不需要**管理员权限，也不需要任何第三方包
- 请遵守游戏相关用户协议，本项目仅供学习与个人娱乐
