# 《起风了》谱图 → 机器谱（识谱脚本留档）

本目录是**一次性识谱流水线**的脚本留档：把 3 张简谱图（`桌面/1.jpg` `2.jpg` `3.jpg`，
后缀是 `.jpg` 但**实际是 AVIF 格式**）转成两个简谱文本，再交给
`获取谱子/jianpu_to_score.py --overlay` 合成机器谱。

## 脚本职责

| 脚本 | 职责 |
|---|---|
| `seg2.py` | 连通块切分 + 三次扫描（黑字 / 灰 tie 音 / **灰八度点**）+ 小节线检测。产出 `glyphs2.json` |
| `split_wide.py` | 把**相邻数字粘连**成的宽块（`15<=w<=34`）按纵向投影低谷切开 |
| `cluster.py` | 字形聚类（每字按自身对比度归一化，`bd<=0.18`），产出 `glyphs3.json` |
| `trans3.py` | 转写 + **逐小节拍数自检**（变拍号、减时线归组、附点、八度点、增时线） |
| `gen_jianpu.py` | 从 `glyphs3.json` 生成两个简谱文本 |
| `run.py` | 一条命令跑通 `seg2 → split_wide → classify → trans3` |
| `audit2/3/4.py` | 独立审计：同素材段落逐字比对 / 时长 / 静音占比 / **逐格键集合对账** |
| `diag24.py` | 像素取证样板（打印指定区域的 ASCII 像素图 + 块清单） |

## ⚠️ 五条最贵的教训（下次别再踩）

1. **附点写「点后缀」`2/.`**，不能写 `·2/`。
   `jianpu_to_score.py` 有 `.replace("·", "0")` —— `·` 是**休止符**的等价写法，
   `·2/` 会折成 `02/` → `无法识别的记谱 token：'02/'`。
   附点在**减时线之后**；和弦同理：`(6, 2)//.`。

2. **八度点与「在哪一行谱表」无关**（影响最大，一度让全曲塌成中音）。
   别把五线谱的加线思维搬过来：**简谱数字不带任何八度信息，八度只能靠上下点表达**。
   唯一正法：**点上 → `'`，点下 → `,`，无点 → 中音**（mel/bas 一视同仁）。
   马脚：产物「只用 13 键、音域仅 22 半音」；改后立刻 20 键 / 35 半音。

3. **点与数字的垂直间隙必须卡 `[2, 21]`**（`trans3.OCT_DOT_MAXGAP`）。
   不卡上限 → 数字下方 ~25px 的**歌词汉字笔画 + 下一行减时线碎块**被当成下加点。
   实测 846 个候选是干净双峰：2~20.5 真点 537 个 / 21.5~44 假点 309 个，
   **21.0~21.5 之间零样本**。症状：`连音线两端的音不一样`。

4. **一个点只能归给「最近的那个数字」**（横向差 ≤9px；真点实测 |Δcx| ≤3）。
   用「±12px 内都算」→ 相邻 9px 的两个数字共享一个点 →
   破坏「同素材段落逐字相同」这条核验口径。

5. **灰音符的八度点是空心小圈（`+#+ / #+# / +#+`），4 连通必碎成 1px 孤点**，
   `merge_fragments` 也吞不掉（灰数字 y319-335、点 y311-313，`313 >= 319-2` 为假）。
   → `seg2.gray_blobs()` 用 **8 连通**；`gray_dots()` 用 `<190` 阈值、
   只收 `2<=h<=6 & 2<=w<=8 & pix>=4`、且须紧挨某个灰数字（x 投影重叠 ±3、垂直间隙 ≤12）。
   症状同样报 `连音线两端的音不一样`，且**只在重复段落里灰音漏点**。

## 关于 `jianpu_to_score.py` 的 `!! 拍数` 警告

第 34 / 64 小节（真 `2/4`）会报「是 2 拍，拍号要求 4 拍」——
**这是记账警告，不是产物问题**。`parse_jianpu.problems` 用**统一 4 拍**校验每小节；
而 `render()` 是按**音符自身时值**累加 cursor、**不看小节线**，
实测第 34 小节 `beats=2.00`，cursor 从 132.00 走到 134.00 正好 2 拍。

同理第 25/26、31/32 小节显示 4.5/3.5、7.0/1.0 —— 那是**跨小节连音线 `tie_spans`
把时值挪到新小节**的记账错位，总时值不变。

### 逐格对账的三个坑（`audit4.py` 里都写了注释）

- 格长必须用**整数 195ms**，不能用 `194.8`：0.2ms × 1072 格 = 214ms 漂移，会假报 692 处错。
- `parser` **先累加间隔再记音符** → 首音时刻 = 一格长度（偏移量），重算时要补上。
- 两个声部**同格同键要去重**（960 → 954），否则假报「丢 6 音」。
