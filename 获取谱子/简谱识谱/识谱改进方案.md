## 0. 摘要

34 首曲子的转写过程沉淀出一个核心事实：

> **这套识别器不是"识别不准"，而是"错了不吭声"。**

23 条在案缺陷里，**至少 10 条**的症状完全一致 —— 产物写错、日志无任何 `⚠`、而
`self_check` 的拍数自检报 **全绿**。原因是一句被反复利用的判据：

```
往某一格里塞一颗音、或给某格加一个 `*` —— 都不改变那一格的时值。
```

于是"每小节拍数和"这张网，恰好漏掉了最常见的一类错。本轮改造因此分成两半：

1. **诊断层（诊断学）**：新增 `audit.py`，用**独立于拍数的观测量**把静默错误显式化；
2. **定点修复（治疗学）**：给三连音检测加"**括号必须圈着音符**的合法性判据 + 打标纵向上界"，
   直接修掉缺陷 21 的成因（Zoo 已从 rc=1 变 rc=0）。

### 2.2 规律（把个案升格为**定律**，供后续所有判据复用）

> **L1（拍数守恒盲区）**「每小节拍数和」是**零阶守恒量**。任何**不改变时值**的错误
> —— 塞音、丢音、加 `*`、丢 `*`、八度点归属错、声部归属错 —— 都守恒，
> 因此拍数自检**必然**漏掉它们。
> ⇒ **推论：必须为每一类"不改时值"的错误配一条独立观测量。** 这是 `audit.py` 的全部动机。

> **L2（形态同构必须靠位置/不变量分离）** 当 A 与 B 在形状上同构时，形状判据永远分不开，
> 必须换一个**与形状无关的维度**。已四次撞墙：三连音括号 vs 页眉括号（→ 用**位置**）、
> 波浪线 vs 花括号 vs 小节线（→ 用**翻转次数/贯通率**）、肥点 vs 数字（→ 用**宽高比+填充**）、
> 连音弧 vs 三连音钩（→ 本轮新增：用**长宽比 h/w**）。

> **L3（判据的中间对象会整类消失）** 依赖对象 O 的判据，必须在 O 整类消失时仍有一条退路。
> 缺陷 15 就是 `_arc_flat` 依赖 `arc` 组件、而该曲一个 `arc` 都没剩。

> **L4（计数判等最怕重复元素）** 凡用"数量相等"做判据的地方，必须先证明元素唯一
> （缺陷 13）；`id()` 去重是本项目标准解法。

> **L5（阈值不可跨判据搬运）** 同一个字形在"要认出"与"要排除"两套判据里阈值不同，
> 搬过去必翻车（缺陷 14 的 `_wavy_tall` 0.030/0.600 不能搬到小节线；缺陷 21 的
> `WAVE_RUN_F` 不能当小节线判据）。

> **L6（结构修补必须全消费方可见）** 凡"数出来的版面结构"（span / vbar / box），
> 修补时**所有消费方必须看到同一份数据**（缺陷 18：救回的长线必须同时进 `self.items`）。

> **L7（只清自己算出来的那一类）** 救援/回滚时只清**本通道产生的标记**，
> 不做 blanket `pop`（缺陷 19）。

> **L8（口径必须与消费方一致）** 检测器/审计器复用的几何口径，必须**逐字对齐**被检测
> 对象的口径。本轮新增一例：审计器若把系统上沿放宽 1.2 字高，就会把识别器**没收录**
> 的那一行误判成"已在系统内"，幽灵行判据直接失灵。

> **L9（整行性错误要用跨行不变量检测）** "整行丢失"类错误在单点上与正常音符无异，
> 只有**跨行/列对齐**才暴露：幽灵行 ⇔ 带外行的数字与带内某行 **cx 逐一列对齐**。

> **L10（几何判据可能被"特例"反超 ⇒ 优先语义判据）** 本轮新增实证：试图用"括号自身
> 离系统多远"（几何）区分真假三连音**必然失败** —— 因为**真括号可能比假阳性离得更远**
> （龙卷风真 2.22 字高 vs 悬潮假 1.65 字高）。当几何量在两类上**区间重叠**时，必须换
> **语义量**（"括号底下有没有音符"），而不是继续调阈值。
> ⇒ **推论：调阈值前先确认两类在该维度上不重叠；重叠即换维度。**

## 3. 可复用方法（SOP，已固化为流程）

| # | 方法 | 要点 |
|---|---|---|
| M1 | **三方对照法** | 识别直出 / 交付件 / 放大图证，三者交叉才能定案（尤其八度点、附点） |

└─ audit_all(sp=sys.modules[__name__], pages, rows, head, sections)   # ★ F3/F4

**关键设计**：`audit.py` **不 import 识谱**，而是由调用方通过
`sys.modules[__name__]` 把识谱模块对象传进来（借用 `sp.bar_columns` 这一纯函数）。
这样既避免循环依赖，又让 `audit.py` 可独立测试。

### 5.4 F5 规格：`arc` 宿主 `3` 通道（缺陷 22 自动修）

#### 5.4.1 成因：三条通道缺的是同一个"宿主"

`_find_triplets()` 现有三样东西：

| 通道 | 来源 | 在判据里的角色 |
|---|---|---|
| `smalls` | `kind=="glyph"` ∧ `h ≤ 0.85·med_h` ∧ label 是数字 | **宿主**（主循环 `for g in smalls`） |
| `hls` | `hline` 并成的"臂" ∧ `0.3·med_h ≤ w ≤ 2.6·med_h` | 左右臂（`nbar` 查它） |
| `aas` | `arc` ∧ `0.3·med_h ≤ w ≤ 2.6·med_h` | 弧形臂（`nbar` 回落时查它） |

`3` 一旦与括号钩粘连成一个连通域，`classify()` 会因"认不出 ∧ `a < 0.5·w·h`（细又弯）"
判成 **`arc`**（L622-623）。此时：

1. `kind != "glyph"` ⇒ **不进 `smalls`**（宿主消失）；
2. 即便被"黑字贴线救援"（L1112-1120，`kind in ("junk","arc")` → `glyph`）救回，
   它的 `h` 已被钩撑到 **> 0.85·med_h** ⇒ **仍被 `h` 闸挡掉**；
3. 臂照旧存在（`hls`/`aas` 里都有），但**主循环没有宿主可迭代** ⇒ `nbar(g)` 从不被调用。

⇒ 这不是"阈值不准"，而是 **L3（判据的中间对象整类消失）**：宿主这一整类没了，
任何围绕宿主的判据（`nbar` / `nend` / 合法性闸）都无从施加。
**修法不是调阈值，而是给"宿主消失"补一条退路** —— 从 `arc` 内部把 `3` 切回来。

> **⚠️ 落地实测补充（2026-10-10，悬潮 p1s4 图证 + 逐行像素探针）**：
> 真相比上面的设计假设更具体 —— 这份漏检有**三重成因**，只补"切字"一条**不生效**：
>
> 1. **细体 `3` 被 `classify` 判成 `arc`** —— 它的 `area 67 < 0.5·w·h = 82.5`（笔画细），
>    落进 `classify` 最后那条 `a < 0.5·w·h` 分支。实测各层模板距离：
>    正文层 **65.18**（`ACCEPT = 65.0`，**只差 0.18** ⇒ 连「黑字贴线救援」都捞不回）、
>    细体层 **50.60** ⇒ 必须用 `small_templates()` 复认才认得出。
> 2. **括号左臂被阈值化切成 `junk` 碎片** —— 实测 `w9 h3`，因
>    `w < HLINE_WF·med_h = 10.35` 不满足 `hline` 判据 ⇒ 落到 `junk`、**永远进不了 `hls`**，
>    于是 `nbar(g, True)` 必然落空。⚠️ 这**不是**"宿主消失"，而是"臂消失"（L3 的另一半）。
> 3. **打标判据用「数字中心落在括号内」** ⇒ 把 `7` 漏掉（左臂只到 `7` 右缘外 **1px**，
>    `7` 的 `cx` 已在括号左界之外）。必须改成「数字与括号**横向区间有交集**」。
>
> ⇒ 三条都补上后悬潮才真正检出（`0 → 1` 括号/页、`*` `0 → 6`、拍数错 `7 → 5`/112），
> 见 §5.4.8。**教训**：L3 的"中间对象"可能不止一个 —— 宿主与臂**都可能整类消失**，
> 排查时要逐个问"这条判据依赖的对象还在不在"。

#### 5.4.2 新增常量（与 `TRI_PAD_F` / `TRI_TAG_DOWN` 同组）

```python
TRI_ARC_HF = 2.6        # arc 宿主的 h 上限（× med_h）—— 与 hls/aas 的长度上限同口径
TRI_ARC_RATIO = 1.30    # 「高瘦」判据：h ≥ 1.30 × w 才算三连音钩（连音弧 h/w ≈ 1.0）
TRI_ARC_ACCEPT_F = 0.75 # 「从大弧里竖切/取窗」的复认倍数（同 _vsplit_marks 的 0.75·ACCEPT）
                        # ⚠️「小号 arc 直接复认」**不走它** —— 那条用全额 ACCEPT（实测 d=50.60）
```

> `TRI_ARC_RATIO = 1.30` **不是新拍的**：它是 §5.3 里 `TRIPLET_ARC` 判据（悬潮 w15×h30
> = 2.0；Zoo 连音弧 w17×h17 / w19×h17 ≈ 1.0）的**同一个标定值**。两处必须逐字一致（L8）。

#### 5.4.3 新增方法

```python
def _extract_digit_from_arc(self, c, med_h, S):
    """从「`3` 与括号钩粘连」的 `arc` 连通域里切出那颗小号数字。

    返回一个 comp（dict）或 None。**不新造识别逻辑** —— 借道既有两条路：

    路 A（首选）_vsplit_marks(c, med_h, S)
        它按竖直方向以「数字高度窗口」逐段认字，且准入自带
          · h > 1.15·med_h（arc 因钩+数字必然满足）
          · 每段 d ≤ 0.75·ACCEPT（**自带质量闸，不会硬凑**）
        取其中 kind=="glyph" ∧ h ≤ 0.85·med_h 的段即可。

    路 B（回落）取 arc 的上半区窗口 y ∈ [y0, y0 + 0.95·med_h]
        （§5.3 的证据：三连音钩是「从数字腰部往下钩」，数字在钩的**上方**），
        _mkcomp(win) 后 match_glyph_shift(norm_cover(win))，
        d ≤ TRI_ARC_ACCEPT_F·ACCEPT 且 label 是数字才收。
        ⚠️ 路 A / 路 B **必须互斥**（路 A 命中即返回），否则同一颗 `3`
           被认两次 → 伪和弦（L4：计数判等最怕重复元素）。
    """

def _arc_digit_cands(self, zones, med_h, S):
    """arc 宿主候选池：**两条互斥的路**（设计期只有 ②，落地实测出 ① 后补齐）。

    ① 「尺寸本身就是一个小号数字」→ 细体层复认；
    ② 「高瘦大弧」→ 从里面切字（`3` 与括号钩粘连的形态）。
    """
    out = []
    tl = small_templates()              # 细体层（含 calibrate 学到的字形）
    for c in self.items:
        if c["kind"] != "arc":
            continue
        if not any(z0 <= c["cx"] <= z1 and z2 <= c["cy"] <= z3
                   for z0, z1, z2, z3 in zones):
            continue                    # 必须落在某系统谱表的有效区内
        # ① 尺寸本身就是「一个小号数字」→ 细体层复认（悬潮的细体 `3`）
        if 0.30 * med_h <= c["h"] <= 0.85 * med_h and c["w"] <= 0.90 * med_h:
            d, lab = match_glyph_shift(norm_cover(c), tl)
            if d <= ACCEPT and str(lab).isdigit():
                g = dict(c)             # 副本 ⇒ 不污染原 arc（后续不改它）
                g["kind"], g["label"], g["dist"] = "glyph", lab, d
                out.append(g)
                continue
        # ② 「高瘦大弧」→ 从里面切字（`3` 与括号钩粘连的形态）
        if c["h"] > TRI_ARC_HF * med_h or c["h"] < TRI_ARC_RATIO * c["w"]:
            continue                    # 连音弧（h/w≈1.0）整类出局
        g = self._extract_digit_from_arc(c, med_h, S)
        if g is not None:
            out.append(g)
    return out
```

> ⚠️ **两条路的顺序不能换、也不能合并**：路 ① 的尺寸闸（`0.30~0.85·med_h`）与
> 路 ② 的「高瘦」闸（`h ≥ 1.30·w`）**判的是不同形态**，而 `continue` 保证
> **同一颗 arc 至多产出一颗宿主** —— 否则同一颗 `3` 被认两次 ⇒ 伪和弦
> （**L4**：计数判等最怕重复元素；这是设计期「路 A/路 B 必须互斥」那条约束的落地形态）。
> 另注意路 ① **不走** `TRI_ARC_ACCEPT_F`，用的是**全额 `ACCEPT`**（实测 `d = 50.60`，
> 余量充足；若卡到 0.75 倍反而会把某些细体字误收为 arc 宿主 —— 见 §5.4.2 注释）。

#### 5.4.4 接入 `_find_triplets()`（对现有代码零侵入）

⚠️ **一处必要的结构调整**：现在 `zones = self._triplet_zones()` 在
`if not smalls: return` **之后**（L1471-1474），而 F5 的候选池需要 `zones`。
`_triplet_zones()` 是**纯函数、无副作用**（只读 `self.spans` / `self.items`），
把它上移到 `smalls` 之前不改变任何行为 —— 但**仍须 A/B 验证**。

```python
        med_h, S = self.med_h, self.S
        self.triplets = []
        # ★ F5 前置：zones 必须在 smalls 之前算（候选池要用；纯函数、无副作用）
        zones = self._triplet_zones()
        smalls = [c for c in self.items if c["kind"] == "glyph"
                  and c["h"] <= 0.85 * med_h and str(c.get("label", "")).isdigit()]
        # ★ F5：第四条通道 —— `3` 与括号钩粘连成 arc 时，「小号数字」这条通道整类落空
        #   （L3）。由 `--triplet-arc` 门控（默认关）；开启后只做「候选池取并集」，
        #   其余流程（nbar / nend / _triplet_encloses_notes）**一行不动**。
        if TRIPLET_ARC and zones:
            smalls = smalls + self._arc_digit_cands(zones, med_h, S)
        if not smalls:
            return
        # ★ F5 第二处：括号臂被阈值化切成细短碎片时会被判成 `junk`
        #   （悬潮实测左臂 `w9 h3`，因 `w < HLINE_WF*med_h = 10.35` 落到 junk）
        #   ⇒ `nbar` 永远找不到它、整组静默漏检。把「很扁 + 不太短」的碎片也纳入并臂候选。
        raw = [c for c in self.items if c["kind"] == "hline" and c["h"] <= 5 * S]
        if TRIPLET_ARC:
            raw += [c for c in self.items
                    if c["kind"] == "junk" and c["h"] <= 0.30 * med_h
                    and c["w"] >= 0.25 * med_h]
        raw.sort(key=lambda c: (c["cy"], c["x0"]))
```

**第二处结构调整（落地实测新增）**：`raw` 的构造要**就地补一段**，把
`kind == "junk" ∧ h ≤ 0.30·med_h ∧ w ≥ 0.25·med_h` 的扁碎片并入并臂候选。
安全性由**下游三道既有闸**兜住（同高相接 Δcy ≤ 2S、臂长 ∈ [0.3, 2.6] 字高、
穿过数字中段），且整段由 `--triplet-arc` 门控（默认关）⇒ 默认态零影响。
> ⚠️ 注意此处**不能**顺手把 `hline` 的 `h <= 5*S` 放宽 —— 那会改到默认路径（红线）。
> 正确做法是**新增并集项**，而不是修改既有筛选条件（L7：只动自己那一类）。

#### 5.4.5 为什么"合法性闸"不能省

`_arc_digit_cands()` 已经把宿主限定在 `zones` 内，但主循环里的
`self._triplet_encloses_notes(x0, x1, yb, zones)` **仍必须照跑**。理由：

* `zones` 约束的是 **宿主（`3`）自己**的位置；
* 合法性闸约束的是 **括号底下那一行音符**的存在性。

两者是不同对象、不同语义。省掉后者会把 F1 立下的语义判据降级成位置闸 ——
正是 §4.1 脚注里已回归过一次的错误（L7：只做/只清自己那一类）。

#### 5.4.9 修法：**渠道隔离**（L7：只动自己那一类）

两处回归是**同一个错误的两半** —— **把「新通道」的能力开给了「老对象」**：

| # | 违规点 | 修法 |
|---|---|---|
| 1 | `_tag_triplet_digits` 用 `if TRIPLET_ARC:` 放宽打标 | 改成 **`if (x0,x1,yb) in self._arc_bars:`** —— 只有 **arc 来源**的括号才放宽 |
| 2 | `raw += junk碎片` 污染了**共用**的 `hls` | 新开 **`hls_x = self._arms_with_junk(hls, med_h, S)`**（拷贝臂 + 并碎片）；`nbar` 按 **`g["_src"] == "arc"`** 分流 |

配套：`_arc_digit_cands()` 产出的宿主一律打 `_src = "arc"`；
`_find_triplets` 接受括号时把 arc 来源的记进 `self._arc_bars`。

**默认态等价性**：`hls_x is None` ⇒ `pool = hls`（逐字同路径）；`_arc_bars` 恒空 ⇒ 恒走紧判据。
⇒ 相对基线的删除行 **4 → 6**，新增的两处（`nbar` 的 docstring、`for L in hls:`）
在默认态**都退化为原语句**。

> **新教训（可升级为 L 级）**：
> **新通道的「能力」必须绑定到「它自己识别出来的对象」，而不是绑定到「可用的输入」。**
> junk 碎片是 F5 挖掘出来的**新证据**，但把它喂进**共用**的 `hls`，等于让**老路径**
> 也获得了新能力 —— 而老路径的对象（既有小号 `3`）从未按新证据校准过。
> **判别口径**：给某条通道放大能力前，先问「**这条能力作用的对象，是不是我自己算出来的？**」
> 若答案是「不是」，就必须**新开一个池/集合**把它隔离（`hls_x` / `_arc_bars`）。

### 5.5 F6 规格：幽灵行自动并入同列和弦（缺陷 20/23）

#### 5.5.1 成因：两条既有救援都是"本行连续性"型判据

| 缺陷 | 既有通道 | 为什么失效 |
|---|---|---|
| 20 | `_rescue_top()`：窗口 `lo = sy0 − SYS_PAD_TOP·med_h`（**0.42 字高**） | 该行整行印在花括号之上、离上沿 **> 0.42 字高** ⇒ 窗口够不着 |
| 23 | `_rescue_top_chain()`：门控 `if abs(sy0 − first_cy) > CUT_TOL·med_h: return []` | 更高（1~2 字高）。此时小节线上沿**合法**地停在两行之间的空档（不是被画短）⇒ 门控判为"正常排版"直接返回空 |

两条通道的共同局限：**判据都是"逐颗看它与本系统的距离/对齐"**。
整行丢失需要在**行与行之间**才能看见 —— 即 **L9（整行性错误要用跨行不变量检测）**。

> ⚠️ 这个错误**不改时值**（塞进同列 = 加一颗和弦音），所以 `self_check` 的
> 拍数自检**必然全绿**（L1）。雨爱 / 龙卷风在案就是"产物错、日志无 `⚠`、自检全绿"。

#### 5.5.2 判据（**与 `audit.ghost_rows` 同源同值**）

对每个系统 `si`：

1. **带内行集合 `R_in`**：`glyph` ∧ `h ≥ 0.8·med_h` ∧ `cx ∈ (cols[0], cols[-1])`
   ∧ `cy ∈ [sy0 − 3S, sy1 + 3S]`（**与识别器同口径，不加 pad** —— L8 的实证；
   审计器早先加了 1.2 字高 pad 就整片失灵）；按 `cy` 用 `_cluster_rows(tol=12S)` 聚成行。
2. **带外窗口**：`hi = sy0 − 3S`（= 识别器"本应收录但没收"的下界），
   `lo = max(sy0 − GHOST_UP_F·med_h, prev_bot + 0.5·med_h)`，其中
   `prev_bot = self.spans[si-2][1]`（`si == 1` 时取 `0`）—— 与 `_rescue_top_chain` 的 `lo` **同口径**，绝不跨上一系统。
3. **带外行集合 `R_out`**：同口径在 `[lo, hi)` 内聚行。
4. **匹配（跨行不变量）**：对 `R_out` 的每一行 `r`，若存在 `R_in` 的行 `s`
   使 `|{cx_r} ∩ {cx_s}| / len(cx_r) ≥ GHOST_ALIGN_F`（`_cluster_rows` / `cx` 容差
   `COL_ALIGN_PX = 4.0` 与 audit 逐字一致），则 `r` 是**幽灵行**。
5. **护栏**：
   * 只收 `h ≥ 0.8·med_h` 且 label 是数字（段落号 / 变拍号出局，同 `_rescue_top`）；
   * `GHOST_MIN_DIGITS = 2`：一行至少 2 颗数字才认作"行"（单颗孤立物可能是上一系统的坠点或装饰记号）；
   * 候选须 `id(c) not in {id(x) for x in saved}` —— `_rescue_top` 已救回的**必须剔除**，
     否则二次追加（L4；`_rescue_top_chain` 的 `_base_ids` 就是这条教训）；
   * `lo` 已钳住，不跨上一系统。
6. **并入语义 —— 不新造任何时值逻辑**：把幽灵行的每颗数字按自己的 `cx` 追加进
   `inner_of[bar]`（`bar = self._bar_of_x(cols, c["cx"])`）。之后 `_bind_system()`
   会按 `bound` 给它 `staff`、`_row_bands()` / `dot_map()` 会因"`cx` 与下方某个音对齐
   而 `cy` 不同"把它自然配成**同列竖排和弦** —— 与 `_rescue_top` 完全同一机制，
   时值继承该列，**不新增拍数**。

#### 5.5.3 落点（`Page._layout` 内，一次插入）

#### 5.5.4 三级门控（**建议先只上 `report`**）

`--ghost-merge {off,report,merge}`，默认 `off`：

| 取值 | 行为 | 产物风险 | 用途 |
|---|---|---|---|
| `off` | 不执行 | 无 | 默认路径（34 首逐字节） |
| `report` | **只打日志、不并入** | **无** | 等价于把 audit 的 `GHOST_ROW` 提前到识别期；先让错误"不再静默" |
| `merge` | 真并入 | 有 | 目标曲修复 |

#### 5.5.5 验收

| 档 | 口径 |
|---|---|
| `off` | 34 首**逐字节不变** |
| `report` | 产物不变；日志新增"幽灵行 N 颗"，且与 `--audit` 的 `GHOST_ROW` **对得上**（同源同值 = L8 的直接检验） |
| `merge` | **只允许**雨爱 / 龙卷风变化；目标小节 `mel` 行的**音数增加而拍数不变**（反向验证 L1）；新增和弦若触发 `CHORD_DESC`，说明八度点归属需另配 —— 列为已知风险 |
| **红线** | `merge` 后**任何**小节拍数变化 ⇒ 立即回退（说明有数字被当成增时线/减时线消费了） |

> ⚠️ **验收陷阱（2026-10-10 实测踩到）**：`-q / --quiet` 会把 `Page.quiet` 置真，
> 而 `Page.log()`（L1431-1433）在 quiet 时**直接 return** ⇒ `report` 档的「幽灵行」
> 日志**一条都不会出现**。第一次做雨爱 / 龙卷风对值时误加了 `-q`，
> 结果「识别期 0 条 vs 审计期 3 条」，看着像判据不同源 —— 实为**日志被自己静默**。
> ⇒ **对值验收必须去掉 `-q`**；常规回归（`one.sh`）带 `-q` 是**故意的**
> （只比产物，不看日志）。

> ⚠️ **对值时还要扣掉一类**：`audit` 会把「**已被上沿救援收进 `box`**」的整行
> 报成 `INFO`（《悬潮》p2s7、《龙卷风》p2s5 即此例），而 `_ghost_row_cands()`
> **显式剔除 `base`**（防二次追加，L4）⇒ 这类**预期不出现在 `report` 日志里**。
> 口径 = **`audit` 的 `WARN` 才与 `report` 对齐**，`INFO` 不参与对值。

| 旋律产物 | 只**加音**：`7. 3'/ ~3' -` → `(2' 7). 3'/ ~3' -` | 只**加音**：`3'/* 2'/* …` → `(5' 3')/* (4' 2')/* …` |
| 时值符号 / `*` 数量 | **未变** | **未变**（10 → 10） |
| 伴奏产物 | **逐字节相同** | **逐字节相同** |

★ **两个独立的反向验证**（不靠"看起来对"）：

1. **`GHOST_ROW` 的 `WARN → INFO`** —— `audit` 这一档的判据就是「这些数字是否出现在
   `pg.box` 里」。降级即**证明并入确实把它们放进了 `box`**；这是从**消费方**回读得到的
   证据，而不是从产物 diff 反推的（**L8 的"消费方回读"用法**）。
2. **`merge` 前后拍数自检同为 `0 错`** —— 佐证「只加音、不改时值」这条设计主张（**L1 的正向对照**）。

> ⚠️ 注意 `merge` 后的产物 diff **不能简单读成"没动时值"** ——`(2' 7).` 里那个 `.`
> 仍是原来 `7.` 的附点，只是把 `2'` 并进了同一列。判"时值未变"要**看符号是否位移**，
> 而不是看行是否变化（行必然变）。

|---|---|---|---|
| `greport` | `--ghost-merge report` | vs 默认（`new2`） | ★ **38 首逐字节相同，0 差异** ⇒ **report 档确认零副作用**（只打日志） |
| `gmerge` | `--ghost-merge merge` | vs 默认（`new2`） | **26 首相同，12 首有差异** |

**受影响的 12 首**（设计只预计 2 首）：
`7龙卷风`、`8稻香`、`9Zoo`、`china-p`、`china-x`、`你从未离去`、`夜曲`、`悬溺`、
`我不曾忘记`、`经过`、`若能绽放光芒-`、`雨爱`。

**红线复核（逐小节拍数）**：

| 结果 | 曲目 |
|---|---|
| ✓ 拍数**完全不变**（含 `**0 错**` 者与 `悬溺 7/112`、`我不曾忘记 25/160`、`若能绽放光芒- 3/190`） | 11 首 |
| ⚠️ 拍数变化：`经过` **261/272 → 257/272**（**减少 4 个错小节 = 改善**） | 1 首 |

> ⚠️ **`经过` 这条"红线命中"要正确解读**：它的**页眉自动识别失败**
> （日志首行 `⚠ 页眉没认出来，用默认 1=C 4/4 91`）⇒ 全曲是在**可能错误的拍号**下转写的，
> 261/272 这个"错"是**既有的系统性问题**，与 F6 无关。merge 让它 261→257
> 只是这个已坏基线里的小位移。
> ⇒ **「逐小节拍数不变」这条红线，对页眉识别失败的曲目不是有效判据** ——
> 判据的有效性依赖被测量本身有意义。

★ **`merge` 判定正确性的正面证据**（diff 形态）：加进来的音**一律是下方三度**
（`2'`→`(4' 2')`、`1'`→`(3' 1')`、`7`→`(2' 7)`、`6`→`(1' 6)`），且**时值符号与连音 `~` 全部保留**
—— 这是「和声/低音声部整行印在谱表上方、被静默丢掉」的典型症状。
例（`夜曲`）：
```
< 2' 0/ 2'// 2'// 1'/ 7// 6// ~6// 7/ 1'//
> (4' 2') 0/ (4' 2')// (4' 2')// (3' 1')/ (2' 7)// (1' 6)// ~(1' 6)// (2' 7)/ (3' 1')//
```

> ⇒ **结论**：`merge` 的功能是对的，但「**只允许雨爱 / 龙卷风变化**」这条**预期被推翻**
> （实际 12/38）。F6 的前提（幽灵行是**系统性**缺陷）由此得到印证 ——
> 这也正是它值得修的原因。`merge` **保持默认 off**：影响面广 ⇒ 应由用户逐曲确认后按需开启。

#### 5.6.3 与"44 处引用点"的衔接（**关键决策：方案 A**）

| 方案 | 做法 | 改动面 | 结论 |
|---|---|---|---|
| **A（选）** | 保留原常量名；`main()` 解析参数后 `globals().update(flat(P))`，**一次性把 Params 展平成模块级同名变量** | **44 处引用一行不改** | ✅ 默认时 `P` 的字段值 == 原常量值 ⇒ **逐字节不变** |
| B | 全改成 `P.triplet.pad_f` | 44 处 | ❌ 改动面大、易漂、回归难归因 |

```python
def flat(p: Params) -> dict:
    """嵌套 dataclass → {模块级常量名: 值}（字段名.upper()）。"""
    out = {}
    for grp in asdict(p).values():          # 递归展平
        for k, v in _walk(grp):
            out[k.upper()] = v
    return out
```

⚠️ **四个派生量必须重算**：`BRACE_AF = 120/ref_h²`、`GLYPH_HF = 12/ref_h`、
`GLYPH_AF = 60/ref_h²`、`SMALL_AF = 25/ref_h²`。若 profile 改了 `ref_h` 而不重算这四项，
"改 ref_h 无效"。⇒ `flat()` 内置显式重算，并在文档标注 `(derived)`。

#### 5.6.4 CLI 与优先级

```
--profile PATH       # 读 JSON 覆盖（嵌套键，如 {"triplet": {"arc_ratio": 1.25}}）
--set K=V            # 点号路径、可重复；如 --set triplet.arc_ratio=1.25
--dump-params PATH   # 把当前生效的 Params 落成 JSON（可原样回灌给 --profile）
```

优先级：`内置默认` < `--profile` < `--set` < **既有单值 CLI**（`--ink` / `--accept` / `--eol`）。

> `--accept` 现有实现 `globals()["ACCEPT"] = float(a.accept)` 与方案 A 的
> `globals().update(...)` 是**同一机制**，天然兼容。但**先后顺序必须写死并测试**：
> 建议 `profile/set` 先展平、`--accept` 后覆盖（保持既有语义不变）。

#### 5.6.5 边界：F7 只搬"阈值"，不搬"状态"

`_TEMPLATES` / `SMALL` / `ACCEPT` / `SECTION_HINT` 是**运行时学出来的数据**，
不是可调阈值 ⇒ **不进 `Params`**。它们留给 **F8 的 `jp/runtime.py`** 显式化。
把这两件事拆开，是为了让回归可归因（L1 的工程化版本：一次只改一类东西）。

### 9.5 ⚠️ 教训：脚本的「完成」信息不可信

`ab37.sh new` 在 13m09s 处**被中途终止**：4 首刚开始跑（日志 0 字节）、5 首未启动，
**但 bash 仍继续执行了后面的 `echo "== new 完成 =="`** ⇒ 脚本**误报完成**。
若只看这一行就宣布"38 首全绿"，会把 9 首的空白当成通过 —— **最危险的假阳性**。

**修**：`ab38.sh` 转写后**清点产物数**，`产物 ≠ 期望` 就 `exit 1` 并明说「勿信上面的完成」。

> **通用教训**：**任何"任务成功"的信号，只要它不是由「结果本身」产生的，
> 就必须用结果重新验证一遍**。`echo 完成` / 退出码 / `&&` 全属此类。
> 本次的可用判据有两个：**① 清点产物数**；**② 每首日志里必须有 `总用时`**
> （该行只在 `main()` 末尾打印 ⇒ "日志含总用时" = "这一首真的跑完了"）。
